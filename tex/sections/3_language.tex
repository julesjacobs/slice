\section{The Slice Language and Type System}\label{sec:language}
In this section, we detail our functional probabilistic programming language (\Cref{sec:sub_language}), its types (\Cref{sec:types}), and its type system tracking information crucial for performing type-directed discretization (\Cref{sec:type-system}).

\subsection{The Slice Language}
\label{sec:sub_language}
%
\input{figures/grammar}
%
The syntax of \emph{expressions} (or \emph{programs}) in the \Slice{} language is shown in \Cref{fig:grammar}.
\Slice{} extends a core higher-order functional language with support for probabilistic choices. Most of the constructs are standard: \Slice{} supports constants, variables, comparisons, Boolean operations, conditionals, for loops, pairs, and lists. Constants of the form $\finconst{k}{n}$ denote integer constants from the finite domain $\{\finconst{0}{n}, \finconst{1}{n}, \ldots, \finconst{(n-1)}{n}\}$, which we detail in the next section.
Additional constructs include first-class functions, recursion, and first-class observations, enabling Bayesian reasoning in the presence of evidence. In particular, $\observekw(e)$ conditions the program execution on a Boolean expression $e$ being true. For probabilistic constructs, \Slice{} supports a wide variety of continuous and discrete distributions. \Slice{} supports continuous distributions with one argument (exponential, laplace, etc.) or two arguments (uniform, gaussian, beta, gamma, etc.). Any continuous distribution for which the cumulative distribution function is known and tractable can be easily added to \Slice{}. This includes distributions such as the Poisson distribution, which can be viewed as a continuous distribution that happens to have probability mass on the natural numbers ($P(n) = e^{-\lambda} \lambda^n / n!$), and no mass elsewhere on the real line. The list of distributions currently supported by our implementation is provided in Appendix~\ref{appen:supported-distributions}.

We now introduce the following central objects:
%
\begin{definition}[Join-Semilattices of Cut- and Value Sets]
	\phantom{a}
	\begin{enumerate}
		\item The \emph{join-semilattice of cut sets} is
		%
		$
			\cutsets = \lattice{\{ \clt{x} ~|~ x \in \R \}	\cup \{ \cleq{x} ~|~ x \in \R \}}.
		$
		%
		%
		\item The \emph{join-semilattice of value sets} is 
		%
		$
			\valsets = \lattice{\R}.
		$
	\end{enumerate}

Elements of $\{ \clt{x} ~|~ x \in \R \}	\cup \{ \cleq{x} ~|~ x \in \R \}$ are called \emph{cuts}. Cut sets induce intervals partitioning the reals as follows:
 Given a non-empty cut set $B =\{ \sim_1\!\!x_1, \ldots, \sim_n\!\! x_n \}$ with $x_1 \leq \ldots \leq x_n$, we define
%
\begin{align*}
	\intervals{B} \quad{}={}\quad &
	\begin{cases}
		 \{ (-\infty, x_1) \}& \text{if $\sim_1 = <$} \\
		 %
		 \{ (-\infty, x_1] \}& \text{if $\sim_1 = \leq$} \\
	\end{cases}
	%
	~~\cup~~ 
	 \bigcup_{i=1} ^{n-1}
	 %
	 \begin{cases}
	 	\{ [x_i, x_{i+1}) \}& \text{if $\sim_i = <$ and $\sim_{i+1} = <$} \\
	 	%
	 	\{ (x_i, x_{i+1}) \}& \text{if $\sim_i = \leq$ and $\sim_{i+1} = <$} \\
	 	%
	 	\{ [x_i, x_{i+1}] \}& \text{if $\sim_i = <$ and $\sim_{i+1} = \leq$} \\
	 	%
	 	%
	 	\{ (x_i, x_{i+1}] \}& \text{if $\sim_i = \leq$ and $\sim_{i+1} = \leq$} \\
	 \end{cases} \\
	 %
	 & {}\cup~~~
	 %
	 \begin{cases}
	 	\{ (x_n, \infty) \}& \text{if $\sim_n = \leq$} \\
	 	%
	 	\{ [x_n, \infty)\}& \text{if $\sim_n = <$} ~.
	 \end{cases} 
\end{align*}
%
Moreover, we let $\intervals{\emptyset} = \{(-\infty,\infty)\}$ and $\intervals{\top} = 2^\Reals$, i.e., $\top$ induces the most fine-grained partitioning of $\Reals$. We denote by $\intervals{B}_i$ the $i$-th interval of $\intervals{B}$, assuming $\intervals{B}$ is $0$-indexed, i.e., $i \in \{0,...,n\}$. This leads us to our types:
%
\begin{definition}[Types]
	For $n \in \Nats$, $B \in \cutsets$, and $V \in \valsets$, types $\tau$ adhere to the grammar
	%
	\begin{align*}
		\tau {}::={} &\phantom{|} \textbf{int} 
		\mid \textbf{bool}
		 \mid \tau_1 * \tau_2 
		 \mid \tau_1 \rightarrow \tau_2 
		 \mid \textbf{unit}
		 \mid\listty{\tau}
		 \mid \textbf{ref}(\tau) 
		 \tag{standard types}\\
		 %
		 &|~ \fin{n} 
		 \tag{finite value types}\\
		 %
		 &|~ \float[B; V]
		 \tag{float types}
		  ~,
	\end{align*}
\end{definition}
%
Let us first briefly go over the standard types:  $\textbf{int}$ is the type of integers, $\textbf{bool}$ is the type of Booleans, $\tau_1 * \tau_2$ is the type of (ordered) pairs of $\tau_1$ and $\tau_2$, $\tau_1 \rightarrow \tau_2$ is the type of functions from $\tau_1$ to $\tau_2$, $\textbf{unit}$ is the unit type, and $\listty{\tau}$ (resp.\ $\textbf{ref}(\tau)$) is the type of lists (resp.\ references) over $\tau$.

$\fin{n}$ is the finite type with values $\{\finconst{0}{n}, \finconst{1}{n}, \ldots, \finconst{(n-1)}{n}\}$, i.e., the natural numbers up to $n-1$, where the index ${\#n}$ indicates that those integers stem from a finite type. This information is crucial for inference backends such as \Dice{}, which rely on values being drawn from a finite domain.

The type $\float[B; V]$ deserves special attention. First, it indicates that a given expression evaluates to a real number. The cut set $B$ and the value set $V$ carry additional information crucial for discretization. Intuitively, the cut set $B$ is an overapproximation of the values the expression of type $\float[B; V]$ will be compared to during program execution (where $\cleq{x}$ indicates a non-strict and $\clt{x}$ indicates a strict comparison), and $V$ is an overapproximation of the values the expression can take. If $B = \top$, then the expression is compared to a continuous value (an infinite number of values), such as a continuous distribution. If $B = \emptyset$, then the expression is never compared to a concrete value during program execution. If $V=\top$, then the expression can take on any value in $\R$.

Finally, we say that an expression $e : \float[B;V]$ is \textit{finite-cut} (\emph{infinite-cut}) if $B \neq \top$ ($B=\top$).

\subsection{Typing Rules}\label{sec:type-system}
The typing rules are split into three parts: Rules specific to float types and continuous distributions (Figure~\ref{fig:typing-float}), standard rules for all other language constructs (Figure~\ref{fig:typing-general}), and subtyping rules (\Cref{fig:subtyping}).

To understand the float typing rules, it is helpful to understand how discretization works.
A type $\float$[B; V] is discretized as follows:
%\begin{itemize}
    %\item 
    If $B \neq\top$ is a finite set of cuts, then the type is discretized to a type $\fin{n+1}$ where $n+1 = |\intervals{B}|$ is the number of intervals induced by $B$. For instance, if $B = \{\clt{0.5}, \cleq{0.8}\}$, then the type is discretized to $\fin{3}$, where $\finconst{0}{3}$ represents the interval $(-\infty, 0.5)$, $\finconst{1}{3}$ represents the interval $[0.5, 0.8]$, and $\finconst{2}{3}$ represents the interval $(0.8, \infty)$.
    %\item 
    If $B = \top$, then no discretization is performed, and the type remains $\float$.
%\end{itemize}

To understand the typing rules, keep in mind that the $B$ set needs to be sufficiently fine-grained --- i.e., contain enough cuts --- so that the discretized program has enough information to determine how the original continuous program behaved.

\input{figures/typing-float}

\paragraph{Constants.}
The typing rule \textsc{Float-Const} for float constants states that a constant $c$ can have type $\float[B; V]$ if $\has{V}{c}$. We define $\has{V}{c}$ to mean that either $c \in V$ or $V = \top$. This rule allows float constants to be typed flexibly: the value set $V$ must either contain the constant $c$ or be the top element $\top$ (representing all possible float values). The cut set $B$ can be arbitrary, as constants do not impose any constraints on how the continuous space should be partitioned, but their presence is recorded in $V$ to determine which values are later used in comparisons.

\paragraph{Continuous distributions.} Let us first consider the typing rule \textsc{Continuous-1} for single-argument continuous distributions.
The rule states that the argument $\Gamma \vdash e : \float[B; V]$ with the constraint that $\distinguishes{B}{V}$. The distinguishes predicate is defined as follows:
\begin{definition}
	\label{def:distinguishes}
	Let $B\in \cutsets$ and $V\in\valsets$. We say that \emph{$\distinguishes{B}{V}$}, if $B = \top$ or ($V \neq \top$ and every interval $I$ induced by $B$ contains at most one value in $V$, i.e., $
	\forall I \in \intervals{B}\colon | V \cap I|  \leq 1
	$).
	%$B$ distinguishes $V$ if every interval in $B$ contains at most one value in $V$, or $B = \top$.
\end{definition}
%
The intuition is the following: In order to discretize $\exponential(e)$, it must be the case that $e$ can only take on finitely many values, and that those values can be fully recovered by the discretized program. This means that $\exponential(e)$ cannot be discretized if $e: \float[B; V]$ with $V=\top$. If, however, $V \neq \top$, then the finite set $V$ contains all the values $e$ can take. In that case, if $\distinguishes{B}{V}$, then $B$ will be fine-grained enough to fully recover $e$'s values in the discretization. We will detail this further in \Cref{sec:discretization}.

\paragraph{Comparisons.} 
To understand the typing rules for less-than and less-than-or-equal comparisons, let us first consider a comparison $e < c$ where $c$ is a constant and $e$ is a continuously ranging quantity, i.e., $e : \float[B_1; \top]$ and $c : \float[B_2; \{c\}]$. Intuitively, {if $e$ is discretized, then it must still contain enough information to determine whether $e < c$ is true or false}. Therefore, $B_1$ must contain the comparison $\clt{c}$.
Similarly, if $c$ is not a literal constant, but has type $c : \float[B_2; V_2]$ where $V_2 = \{v_1, v_2, \dots, v_n\}$ is a finite set of constants, then $c$ can take on values in $V_2$. Therefore, $B_1$ must contain the comparisons $\clt{v_1}, \clt{v_2}, \dots, \clt{v_n}$.

It can also be the case that we have a comparison $c < e$ where the continuously ranging quantity $e : \float[B_2; V_2]$ is on the right hand side. In this case, $B_2$ must answer $c\!\!<$, i.e., it must contain a comparison $\cleq{c}$. To make this explicit, consider $2.3 < e$. We can answer this precisely when $B_2$ contains an intervals $(-\infty, 2.3]$ and $(2.3, +\infty)$: the comparison $2.3 < e$ is true if $e$ is in the second interval, and false if $e$ is in the first interval. $B_2$ may, of course, be even more fine-grained.


In general, the typing rule for $e_1 < e_2$ requires that the expressions share a bound set $B$, and that their respective value sets $V_1, V_2$ are related in a way that allows the comparison to be determined after discretization, via the $\answerslt{B}{V_1}{V_2}$ relation:

\begin{definition}
	\label{def:answers-less}
	Let $B\in \cutsets$ and $V_1, V_2 \in\valsets$.
	We say that \emph{$\answerslt{B}{V_1}{V_2}$} if  (1) $B = \top$, or (2) $B \neq \top$ and $V_2 \neq \top$ and $\forall x \in V_1,\ \clt{x} \in B$, or
		(3) $B \neq \top$ and $V_1 \neq \top$ and $\forall x \in V_2,\ \cleq{x} \in B$.
\end{definition}

This definition is subtle and it requires some explanation to understand why it makes sense and ensures that the comparison result can still be determined after discretization.

To understand this definition, we first want to introduce two different perspectives on the $B$ set. The first perspective is that $B$ specifies a set of intervals, such that values of the expression will be mapped to their respective interval index. The second perspective is that this discretized index \emph{still contains enough information to evaluate all comparisons in $B$ when viewed as predicates}. That is, if $B$ contains $\clt{x}$ then, the discretized value of $e : \float[B; V]$ still contains enough information to answer $e < x$ precisely: if after discretization, we have an interval index below the index of $\clt{x}$, then the comparison is false, and otherwise it is true.

Now, if $e_1 : \float[B; V_1]$ and $e_2 : \float[B; V_2]$, then $\answerslt{B}{V_1}{V_2}$ ensures that the comparison result can still be determined after discretization because:

\begin{enumerate}
	\item If $B = \top$, then no discretization is performed, and the comparison can just be performed on the real-valued expression.
	\item If $B \neq \top$ and $V_2 \neq \top$, then the expression is discretized into intervals as determined by $B$, but in this case the right hand side can only take on values in $V_2$. In this case, all $\clt{x}$ for $x \in V_2$ must be contained in $B$, which means that the value of $e_2$ can be exactly recovered from its interval index.
	Then, given the previous observation, we can determine the comparison result by comparing the interval index of $e_1$ to the interval index of $e_2$.
	\item If $B \neq \top$ and $V_1 \neq \top$, then the situation is similar to the previous case.
\end{enumerate}

Note that $B = \top$ iff $V = \top$ accounts for comparisons where a continuously ranging expression is compared against arbitrary real values not statically known, such as other continuous distributions, in which case no discretization can be performed.
Additionally, we insist that $B_1 = B_2$, which ensures that both comparants will be discretized to the same type, or not discretized at all.

%This symmetry ensures that the comparison is always well-typed and meaningful, either as a comparison between two discretized values in the same finite domain, or as a comparison between two real-valued, undiscretized quantities. For example, it ensures that $e$ and $c$ are discretized to the same representation, and $<$ can be discretized to $\finleq{k}$. 


Finally, for non-strict comparisons, the rule is analogous to \Cref{def:answers-less}:
\begin{definition}
	\label{def:answers-less-equal}
	Let $B\in \cutsets$ and $V_1, V_2 \in\valsets$.
	We say that \emph{$\answersleq{B}{V_1}{V_2}$} if (1) $B = \top$, or (2)  $B \neq \top$ and $V_2 \neq \top$ and $\forall x \in V_1,\ \cleq{x} \in B$, or (3) 
	 $B \neq \top$ and $V_1 \neq \top$ and $\forall x \in V_2,\ \clt{x} \in B$.
\end{definition}

\paragraph{Subtyping.}
The type system includes a subtyping relation that captures when one type can be replaced by another. The subtyping rules are shown in Figure~\ref{fig:subtyping}. For float types $\float[B;V]$, subtyping follows the lattice ordering on $V$: An expression known to range over some set of values can also be considered to range over a superset of those values. For $B$, we require equality to make sure that the discretized representation of the expression is not changed by subtyping.

All other typing rules are standard and depicted in Figure \ref{fig:typing-general} and Appendix~\ref{appen:typing-rules}, respectively.
