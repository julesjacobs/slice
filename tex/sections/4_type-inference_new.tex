\section{Type Inference}\label{sec:type-inference-new}

In this section, we describe our type inference algorithm, where the goal is to annotate each subexpression of a program with its most precise type. Specifically, we describe our type inference algorithm for expressions with float type $\float[B;V]$, showing how \Slice{} populates the cut set $B$ and value set $V$ for each float-typed expression, as these refinements will later determine how and whether the expression can be discretized. Type inference for all other types is standard and follows the classic Hindley-Milner type inference algorithm. For our type inference algorithm on float-typed expressions, we follow a standard two-phase approach: the first phase traverses the program once to generate a set of constraints over cut and value sets; the second phase solves these constraints to produce a fully annotated program.

\subsection{Constraint Generation}

We use a constraint language as shown in Figure~\ref{fig:constraints-grammar} to express requirements over type structure and float refinements. We adopt the framework presented in~\cite{Odersky1999ConstrainedTypes}, introducing a new judgment of form $C, \Gamma \vdash e : \tau$, which reads as \emph{in the environment $\Gamma$, $e$ has type $\tau$ and produces the set of constraints $C$}. The inference rules formalize what constraint $C$ must be generated (and later solved) for a given expression $e$ to have inferred type $\tau$. Figure~\ref{fig:type-inference} gives the constraint generation rules for \Slice{}. We focus on a small but representative subset of constructs in \Slice{}, but enough to capture the core features needed to demonstrate how the algorithm operates over the full language.

Several constraint generation rules warrant special attention, which we now mention. In particular, the \textsc{TIf} rule uses the least upper bound operator $\latticesup$ to combine the value sets of the float-typed subexpressions in the two branches of the conditional. This ensures that the resulting value set of the entire entire conditional conservatively approximates all possible outcomes of the conditional expression, regardless of the branch taken at runtime. Notice that the constraints generated by the \textsc{TLess} and \textsc{TLessEq} rules directly correspond to the answerability conditions defined in Definitions~\ref{def:answers-less} and~\ref{def:answers-less-equal}: the constraint $B = \; \clt{V}$ is simply a formulation of the requirement that ``$B$ answers $\clt{V}$''. Additionally, notice that the constraints generated by the \textsc{TContinuous-1} rule for the argument of the distribution directly satisfy the distinguishability condition defined in Definition~\ref{def:distinguishes}. For space, we only show the constraint generation rule for a continuous distribution with one argument; however, the rule for a two-argument distribution is completely analogous, as constraints are generated independently for both arguments.

\begin{figure}[!t]
    \begin{align*}
    C ::= &\; \top \mid \{c_1,\ldots,c_n\} \mid B  \text{ (cut set)} \mid V  \text{ (value set)} \mid C_1 = C_2  \text{ (type equality)} \mid C_1 \land C_2   \text{ (conjunction)} \\
    \end{align*}
\caption{Syntax for our constraint language. As we want \Slice{} to propogate information about comparisons and possible value ranges into float types, our syntax is over $B \in \cutsets$ and $V \in \valsets$.}
\label{fig:constraints-grammar}
\end{figure}

\begin{example}
    To further illustrate how our constraint generation rules work, we walk through an example below. Consider the program, omitting the irrelevant types such as \bool:

    \begin{lstlisting}[aboveskip=1em,belowskip=1em,escapechar=!,mathescape]
        let x = if flip()
                then (uniform(0,2) : !{\ftb{$B_1$}{$V_1$}}!)
                else (gaussian(0,1) : !{\ftb{$B_2$}{$V_2$}}!)
                : !{\ftb{$B_3$}{$V_3$}}! in
        let y = if (1.5 : !{\ftb{$B_4$}{$V_4$}}!) > (x : !{\ftb{$B_3$}{$V_3$}}!)
                then (1.8 : !{\ftb{$B_5$}{$V_5$}}!)
                else (0.3 : !{\ftb{$B_6$}{$V_6$}}!)
                : !{\ftb{$B_7$}{$V_7$}}! in
        x <= y
    \end{lstlisting}

    Recursing through the AST, we obtain the following constraints: 
    \katherine{fix fonts}

    \begin{enumerate}
        \item $B_1 = B_2 = B_3$ and $V_1 \latticesup V_2 = V_3$ \\
        \quad \emph{Generated from the \texttt{if} expression in the right-hand side of the first \texttt{let} binding for $x$, via the rule \textsc{TIf}.}
        \item $B_4 = B_3$ and $B_4 = \; \clt{V_3}$
        \\
        \quad \emph{Generated from the comparison \texttt{1.5 > x} in the guard of the \texttt{if} expression inside the \texttt{let} binding for \texttt{y}, via rule \textsc{TLess}.}

        \item $B_5 = B_6 = B_7$ and $V_5 \latticesup V_6 = V_7$ \\
        \quad \emph{Generated from the \texttt{if} expression in the right-hand side of the \texttt{let} binding for \texttt{y}, via the rule \textsc{TIf}.}

        \item $V_1 = V_2 = \top$, $V_4 = \{1.5\}$, $V_5 = \{1.8\}$, $V_6 = \{0.3\}$ \\
        \quad \emph{Generated from constants and primitive distributions: $V_1$, $V_2$ from \texttt{uniform} and \texttt{gaussian}; $V_4$, $V_5$, $V_6$ from literal constants \texttt{1.5}, \texttt{1.8}, and \texttt{0.3}, via the rules \textsc{TContinuous-2} and \textsc{TFloat-Const}.}
    \end{enumerate}
\end{example}
