\section{Introduction}\label{sec:intro}
Probabilistic programming languages (PPLs) are widely used to model uncertainty~\cite{Moy2025Roulette,Holtzen2020Dice,DeRaedt2007ProbLog,Saad2021SPPL,Carpenter2017Stan,Salvatier2016PyMC3,Bingham2019Pyro,Dillon2017TFP,Tran2016Edward,Tolpin2016Anglican,Goodman2014WebPPL,Pfeffer2009Figaro,Minka2018InferNET,Ge2018Turing,CusumanoTowner2019Gen,Tehrani2020BeanMachine,Goodman2008Church}. Languages with {\em continuous} distributions capture rich models but require reasoning about uncountable domains, whereas purely {\em discrete} languages admit fast and precise inference but cannot express real-valued models.

\Slice{} combines a surface language with a compiler that automatically translates continuous expressions into discrete ones while keeping the program's behavior intact---a process we call \emph{exact discretization}. The type system tracks every constant threshold (or {\em cut}) used in comparisons and leverages them to partition the continuous domains into finitely many intervals. For example, $\uniform(0,1) < 0.5$ discretizes to $\discrete(0.5,0.5) < 1$, producing a purely discrete program that existing exact inference tools can process. 

Cuts may arise far from their source expressions: a sampled value might flow through higher-order functions or data structures before being compared. \Slice{}'s type inference propagates each cut along these flows so that future comparisons remain resolvable, enabling the models in \Cref{sec:examples}. Discretization is subject to a principled restriction: a continuous expression must ultimately be compared against constants; direct comparisons between two unknown reals cannot be discretized exactly and remains continuous.

Discretization itself is not new. Garg et al.~\cite{Garg2024BitBlast} and other approximation schemes~\cite{Huang2021AQUA} encode real-valued variables via user-chosen bit-precisions, trading accuracy for tractability. We instead reserve \emph{exact discretization} for transformations that preserve the original distribution and use \emph{quantization} for approximate techniques such as bit-blasting.

The \Slice{} language is a statically typed functional language with higher-order functions and recursion. Figure~\ref{fig:architecture} outlines the design. Because discretization is a source-to-source transformation, any discrete PPL that supports finite distributions can act as a target. We demonstrate this with \Dice{} and \Roulette{}. Dice delivers up to $90\times$ speedups over \SPPL{} on first-order programs, while Roulette~\cite{Moy2025Roulette} handles higher-order functions and recursion, allowing \Slice{} to support both regimes without changing the compilation pipeline.

\noindent\textbf{Contributions.} Starting from concrete examples (\Cref{sec:examples}), we:
\begin{description}[leftmargin=0.3cm,topsep=3pt,itemsep=1pt]
    \item[Type System (\Cref{sec:language})] Characterize when expressions are discretizable by tracking how they interact with constant thresholds.
    \item[Type Inference (\Cref{sec:type-inference})] Solve for the required cut and value sets automatically.
    \item[Exact Discretization (\Cref{sec:discretization})] Transform programs so that each continuous construct becomes discrete, guided by the inferred cuts.
    \item[Soundness (\Cref{sec:soundness})] Prove that discretization preserves semantics using probabilistic couplings~\cite{Bizjak2015Step,Wand2018Contextual}.
    \item[Implementation and Evaluation (\Cref{sec:implem_eval})] Provide an open-source compiler targeting Dice and Roulette and evaluate it on prior and new benchmarks.
\end{description}
