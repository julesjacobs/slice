\section{Introduction}\label{sec:intro}
Probabilistic programming languages (PPLs) are widely used to model uncertainty~\cite{Moy2025Roulette,Holtzen2020Dice,DeRaedt2007ProbLog,Saad2021SPPL,Carpenter2017Stan,Salvatier2016PyMC3,Bingham2019Pyro,Dillon2017TFP,Tran2016Edward,Tolpin2016Anglican,Goodman2014WebPPL,Pfeffer2009Figaro,Minka2018InferNET,Ge2018Turing,CusumanoTowner2019Gen,Tehrani2020BeanMachine,Goodman2008Church}. Languages with {\em continuous} distributions capture rich models but require reasoning about uncountable domains, whereas purely {\em discrete} languages admit fast and precise inference but cannot express real-valued models.

\Slice{} studies \emph{exact discretization}: a semantics-preserving source-to-source transformation that converts selected continuous behavior into discrete behavior. We target programs where continuous quantities are consumed in a finitely branching, comparison-driven way, so exact inference reduces to a finite problem. The key mechanism is type-directed cut inference: the type system tracks each constant threshold (or {\em cut}) used in comparisons and uses this information to partition continuous domains into finitely many intervals. For example, $\uniform(0,1) < 0.5$ discretizes to $\discrete(0.5,0.5) < 1$, yielding a purely discrete program that existing exact-inference tools can process.

Cuts may arise far from their source expressions: a sampled value may flow through higher-order functions, recursive calls, data structures, and control-flow joins before being compared. \Slice{} propagates cut information along these non-local flows so that later comparisons remain resolvable (Section~\ref{sec:examples}). This non-locality means correctness must be proved semantically rather than by local rewriting: we must relate whole-program behaviors induced by a type-mediated transformation. Discretization is subject to a principled restriction: a continuous expression must ultimately be compared against constants; direct comparisons between two unknown reals cannot be discretized exactly and remain continuous.

Discretization itself is not new. Garg et al.~\cite{Garg2024BitBlast} encode real-valued variables via user-chosen bit-precisions, trading accuracy for tractability. Other approximate discretization schemes exist in the literature~\cite{Huang2021AQUA,Beutner2022GuaranteedBounds,Claret2013BayesianDataFlow}. We reserve \emph{exact discretization} for transformations that preserve the original distribution and use \emph{quantization} for approximate techniques such as bit-blasting.

The \Slice{} language is a statically typed functional language with higher-order functions and recursion. Figure~\ref{fig:architecture} shows one concrete pipeline from typed source programs to discrete backends. Because discretization is source-to-source, any discrete PPL that supports finite distributions can serve as a target; we instantiate this with \Dice{} and \Roulette{}.

\noindent\textbf{Contributions.} Starting from concrete examples (\Cref{sec:examples}), we:
\begin{description}[leftmargin=0.3cm,topsep=3pt,itemsep=1pt]
    \item[Type System (\Cref{sec:language})] Characterize when expressions are discretizable by tracking how they interact with constant thresholds.
    \item[Exact Discretization (\Cref{sec:discretization})] Define a type-directed transformation from continuous constructs to discrete ones using inferred cut information.
    \item[Type Inference (\Cref{sec:type-inference})] Solve automatically for the cut and value sets required by the transformation.
    \item[Soundness (\Cref{sec:soundness})] Prove semantic preservation with a coupling-style relational argument suited to a global, non-local transformation~\cite{Bizjak2015Step,Wand2018Contextual}.
    \item[Implementation and Evaluation (\Cref{sec:implem_eval})] Provide an open-source implementation targeting Dice and Roulette, and evaluate asymptotic scaling behavior and benchmark coverage.
\end{description}
