\section{Slice by Example}\label{sec:examples}
To build intuition for \Slice{}, we start with examples of increasing complexity.

\subsection{Branching on a Single Continuous Variable}\label{sec:examples:1}
We consider a program that samples a real value from a standard Gaussian distribution and then performs two nested comparisons, first checking whether the sampled value is less than 0.8, then comparing that value against either 0.1 or 2.0:

\begin{lstlisting}[aboveskip=1em,belowskip=1em]
    let x = gaussian(0,1) in 
    if x < 0.8 then x < 0.1 else x < 2.0
\end{lstlisting}

\noindent Instead of sampling a real value, we sample the discrete interval containing it, as shown below and in Figure~\ref{fig:cuts-gaussian}:

\input{figures/cuts.tex}

\begin{lstlisting}[aboveskip=1em,belowskip=1em]
    let x = discrete(0.5398, 0.2483, 0.1891, 0.0228) in
    if x < 2 then x < 1 else x < 3
\end{lstlisting}

\noindent Here, \discrete(0.5398, 0.2483, 0.1891, 0.0228) already represents all four observationally distinguishable outcomes of the Gaussian sample. The precise real value of $x$ never mattered to the rest of the program; only the interval in which it falls does. This is the regime we target: continuous quantities used in an observationally discrete way. \textbf{Slice’s goal is to detect such situations automatically.} We partition the continuous expression into intervals that are indistinguishable to the rest of the program, and then map every real to the interval it inhabits. 

The transformation is guided by our type system, driven by a \emph{cut set}: the set of comparison thresholds extracted from the program. A continuous expression is annotated with its cut set (either finite or $\top$, indicating comparison to a continuous value), recording the values it is compared against.

\begin{lstlisting}[aboveskip=1em,belowskip=1em,escapechar=!]
    let x = (gaussian(0,1) : !{\ftnv{<0.2,<0.5,<2}}!) in
    if x < 0.5 then x < 0.2 else x < 2.0
\end{lstlisting}

\noindent Intuitively, the cuts $\{\clt{0.1}, \clt{0.2}, \clt{0.5}\}$ partition the real line $\R$ into four intervals $(-\infty, 0.1)$, $[0.1, 0.2)$, $[0.2, 0.5)$, $[0.5, +\infty)$, and only the interval in which the Gaussian sample $x$ falls affects the rest of the computation. \Slice{} uses these cuts to replace the continuous expression with a discrete one whose outcomes correspond exactly to these intervals, and each floating-point constant is mapped to the index of the interval that contains it.

\subsection{Branching on Multiple Continuous Variables}\label{sec:examples:2}

\noindent Different expressions may induce different cut sets, and \Slice{} computes the appropriate set for each expression independently. Consider an example with multiple continuous variables:

\begin{lstlisting}[aboveskip=1em,belowskip=1em]
    let x = uniform(0, 1) in
    let y = uniform(0, 2) in
    if x < 0.5 then x < 0.2 else y < 0.1
\end{lstlisting}

\noindent In this program, the variable $x$ is drawn from \uniform(0, 1) and is compared against two different constants: $0.5$ and $0.2$. These two cuts $\clt{0.5}$ and $\clt{0.2}$ partition the real line $\R$ into three intervals: $(-\infty, 0.2)$, $[0.2, 0.5)$, and $[0.5, +\infty)$. Similarly, the variable $y$, drawn from \uniform(0, 2), is compared only with $0.1$. This single cut $\clt{0.1}$ partitions the real line $\R$ into two intervals, $(-\infty, 0.1)$ and $[0.1, +\infty)$.

Type inference performs this analysis by collecting all cuts for each continuous variable. For $x$, it discovers the cuts $\clt{0.2}$ and $\clt{0.5}$, giving it the type \ftnv{<0.2,<0.5}. For $y$, it only finds $\clt{0.1}$, giving it the type \ftnv{<0.1}. This information is captured in the annotated program below (omitting the redundant types):

\begin{lstlisting}[aboveskip=1em,belowskip=1em,escapechar=!]
    let x = uniform(0, 1) : !{\ftnv{<0.2,<0.5}}! in
    let y = uniform(0, 2) : !{\ftnv{<0.1}}! in
    if x < 0.5 then
      x < 0.2
    else
      y < 0.1
\end{lstlisting}


\Slice{} therefore discretizes $x$ into three outcomes \discrete(0.2, 0.3, 0.5) and $y$ into two outcomes \discrete(0.05, 0.95), where each probability is the measure of the original interval. Comparisons now operate over the integer indices of those intervals:

\begin{lstlisting}[aboveskip=1em,belowskip=1em]
    let x = discrete(0.2, 0.3, 0.5) in
    let y = discrete(0.05, 0.95) in
    if x < 2 then x < 1 else  y < 1
\end{lstlisting}

\noindent The constants $0.5$ and $0.2$ map to indices 2 and 1, respectively, in the partition $(-\infty,0.2)\cup[0.2,0.5)\cup[0.5,+\infty)$ for $x$. The constant $0.1$ maps to index 1 in the partition $(-\infty,0.1)\cup[0.1,+\infty)$ for $y$.

\subsection{Discretizing Float Constants}\label{sec:examples:3}
The example in Section~\ref{sec:examples:2} involves comparisons with literal constant right-hand sides (such as $e < 0.5$). 
\Slice{} does not require the comparison to have a syntactic constant right-hand or left-hand side. Instead, it analyzes the dataflow of the program to determine which constants are relevant, and how these constants are mapped to discrete indices.
Consider the program:

\begin{lstlisting}[aboveskip=1em,belowskip=1em,escapechar=!]
    let x = if flip() then 0.2 
            else if flip() then 2.5
            else 4.5 in 
    let y = 0.5 in x < y
\end{lstlisting}

This yields the annotated program after type inference:

\begin{lstlisting}[aboveskip=1em,belowskip=1em,escapechar=!]
    let x = if flip() then (0.2 : !{\ftb{<0.5}{0.2}}!)
            else (if flip() then (2.5 : !{\ftb{<0.5}{2.5}}!)
            else (4.5 : !{\ftb{<0.5}{4.5}}!) 
            : !{\ftb{<0.5}{2.5, 4.5}}!)
            : !{\ftb{<0.5}{0.2, 2.5, 4.5}}! in
    let y = 0.5 : !{\ftb{<0.5}{0.5}}! in x < y
\end{lstlisting}

Both $x$ and $y$ can only take on finitely many values --- a fact which is reflected by the value sets in the type annotations. By locating where each value in the value set falls relative to the cuts in the cut set, \Slice{} determines the corresponding interval index for each value. \codetype{\ftb{<0.5}{0.2}} corresponds to the index 0, and types \codetype{\ftb{<0.5}{2.5}}, \codetype{\ftb{<0.5}{4.5}}, and \codetype{\ftb{<0.5}{0.5}} all correspond to the index 1. The value sets in types \codetype{\ftb{<0.5}{0.2, 2.5, 4.5}} and \codetype{\ftb{<0.5}{2.5, 4.5}} arise from taking the union of the value sets from each prior conditional branch. This in turn yields the following discretized program:

\begin{lstlisting}[aboveskip=1em,belowskip=1em]
    let x = if flip() then 0
            else if flip() then 1
            else 1 in
    let y = 1
    x < y
\end{lstlisting}

Notice how both $2.5$ and $4.5$ are discretized to $1$, because for the purpose of comparing them to $y = 0.5$, these values are equivalent.

\subsection{Control flow}\label{sec:examples:4}

We now consider comparisons against an expression for which control flow determines which of several constant values it may take. Additionally, continuous values can flow through conditionals before reaching such a comparison:

% \begin{lstlisting}[aboveskip=1em,belowskip=1em,escapechar=!]
%     let x = if flip() then uniform(0,2) else gaussian(0,1) in
%     let y = if 1.5 > x then 1.8 else 0.3 in x <= y
% \end{lstlisting}

\input{figures/cf-program.tex}

\noindent Here, $y$ evaluates to either $1.8$ or $0.3$ depending on $x$. Because $x \leq y$ may use either value, \Slice{} collects both constants and treats the comparison as over this finite set. This motivates enriching our float types with a \emph{value set}: a finite collection of concrete values that an expression may evaluate to. Figure \ref{fig:float-type-def} presents the full float type as is implemented by \Slice{}; each floating-point expression is annotated with such a type. The type-annotated program is thus (omitting the redundant and irrelevant types):

\begin{lstlisting}[aboveskip=1em,belowskip=1em,escapechar=!]
    let x = if flip()
            then (uniform(0,2) : !{\ft{<=0.3,<1.5,<=1.8}}!)
            else (gaussian(0,1) : !{\ft{<=0.3,<1.5,<=1.8}}!)
            : !{\ft{<=0.3,<1.5,<=1.8}}! in
    let y = if (1.5 : !{\ftb{<=0.3,<1.5,<=1.8}{1.5}}!) > x
            then (1.8 : !{\ftb{<=0.3,<1.5,<=1.8}{1.8}}!)
            else (0.3 : !{\ftb{<=0.3,<1.5,<=1.8}{0.3}}!)
            : !{\ftb{<=0.3,<1.5,<=1.8}{0.3,1.8}}! in
    x <= y
\end{lstlisting}

\noindent Value sets refine an expression's cut set by contributing cuts at comparisons. For example, in the test $x \leq y$, the value set of $y$ contributes boundary points that must also appear in the cut set of $x$. This dependency is non-local: constants introduced in one branch can constrain how a sampled value from another branch must be discretized.

More generally, whenever two expressions are compared, the type system equates their cut sets so they are discretized over the same intervals. These cut sets then propagate backward through the control flow to all contributing subexpressions. Figure~\ref{fig:control-flow-gaussian} illustrates this non-local propagation, which the soundness proof must relate through a semantic coupling relation.

\input{figures/cf-propagation.tex}

Now, the discretized program becomes:

\begin{lstlisting}[aboveskip=1em,belowskip=1em]
    let x = if flip() then
        discrete(0.15, 0.6, 0.15, 0.1)
      else
        discrete(0.617911, 0.315281, 0.0308769, 0.0359303) in
    let y = if 1 > x then 2 else 0 in
    x <= y
\end{lstlisting}

\noindent The cuts $\cleq{0.3}$, $\clt{1.5}$, and $\cleq{1.8}$ induce the intervals $(-\infty, 0.3]$, $(0.3, 1.5)$, $[1.5, 1.8]$, and $(1.8, +\infty)$; the strict comparison excludes 1.5 from the second one. Each \discrete-expression lists the mass of those four intervals. For instance, \uniform(0,2) assigns $(0.15, 0.6, 0.15, 0.1)$. 

\begin{figure}
    \[
    \textbf{float}
    [
    \underbrace{\text{cut-set}}_{\footnotesize\begin{array}{c}\text{set of cuts}\text{ (e.g., }\{<\!0.1, <\!0.5, \leq\!0.8\}\text{)}\\\text{or }\top\text{ (uncut)}\end{array}}
    ;
    \underbrace{\text{value-set}}_{\footnotesize\begin{array}{c}\text{set of concrete values }\text{(e.g., }\{0.1, 0.4, 0.5\}\text{)}\\\text{or }\top\text{ (any continuous value)}\end{array}}

\subsection{Discrete Latent Variable}\label{sec:examples:5}

Continuous distributions can have parameters that depend on discrete random choices. In this example, a Gaussian distribution's standard deviation is determined by such a random choice:

\begin{lstlisting}[escapeinside={<@}{@>},aboveskip=1em,belowskip=1em]
    let x = if flip() <@\textcolor{purple}{then}@> 0.5 <@\textcolor{purple}{else}@> 1.5 in gaussian(0, <@\textcolor{red}{x}@>) <@\textcolor{orange}{<}@> 0.5
\end{lstlisting}

\noindent %This example shows how discrete choices can affect the parameters of continuous distributions. 
The type-annotations reveal how the variable $x$ determines the standard deviation of the Gaussian, and Figure~\ref{fig:control-flow-distinguishes} illustrates how type information is propagated:

\begin{lstlisting}[aboveskip=1em,belowskip=1em,escapechar=!]
    let x = if flip() then (0.5 : !{\ftb{<=0.5,<=1.5}{0.5}}!)
        else (1.5 : !{\ftb{<=0.5,<=1.5}{1.5}}!)
        : !{\ftb{<=0.5,<=1.5}{0.5,1.5}}! in
    (gaussian(0, x) : !{\ft{<0.5}}!) < (0.5 : !{\ftb{<0.5}{0.5}}!)
\end{lstlisting}

\input{figures/latent-variable.tex}

\noindent Because $x$ is later used as a parameter to $\gaussian$, \Slice{} generates one case per value in its value set (0.5 and 1.5). To support this, the type system uses non-strict inequalities in cut sets, allowing these values to map to unique integer indices starting at 0. Specifically, 0.5 maps to index 0 via \codetype{\ftb{<=0.5,<=1.5}{0.5}}, and 1.5 maps to index 1 via \codetype{\ftb{<=0.5,<=1.5}{1.5}}. This is a non-local effect: an upstream discrete latent choice determines how a downstream continuous distribution is discretized. The resulting discretized program then branches on these values and instantiates the corresponding discrete distribution for the standard deviation selected by the initial flip:

\begin{lstlisting}[aboveskip=1em,belowskip=1em]
    let x = if flip() then 0 else 1 in
    (if x == 0 then  discrete(0.841345, 0.158655)
               else  discrete(0.630559, 0.369441)) < 1
\end{lstlisting}

\subsection{Conditioning}\label{sec:examples:6}

\Slice{} supports conditioning via $\observekw$. The program below (already type-annotated) computes $\Pr[x<0.2 \mid x<0.5]$ for $x \sim \uniform(0,1)$:

%\begin{lstlisting}[aboveskip=1em,belowskip=1em,escapechar=!]
%    let x = uniform(0.0, 1.0) in
%    let _ = observe (x < 0.5) in
%    x < 0.2
%\end{lstlisting}
%
%\noindent The type annotations show how observation points become cuts:

\begin{lstlisting}[aboveskip=1em,belowskip=1em,escapechar=!]
    let x = (uniform(0.0, 1.0) : !{\ft{<0.2,<0.5}}!) in
    let _ = observe (x < (0.5 : !{\ftb{<0.2,<0.5}{0.5}}!)) in
    x < (0.2 : !{\ftb{<0.2,<0.5}{0.2}}!)
\end{lstlisting}

\noindent Discretization again replaces reals by interval indices:

\begin{lstlisting}[aboveskip=1em,belowskip=1em]
    let x = discrete(0.2, 0.3, 0.5) in
    let _ = observe (x < 2) in
    x < 1
\end{lstlisting}

\noindent Observation $x<2$ eliminates the discrete state corresponding to the original interval $[0.5,+\infty)$, mirroring the conditioning on $x<0.5$.

Exact equalities can be encoded with $\observekw\; (x \leq c \mathrel{\&\&} x \geq c)$. Measure-zero observations remain delicate~\cite{Jacobs2021ParadoxesProbProg}; our semantics handles them by recording observation failure mass instead of renormalizing, so discretization preserves an even stronger equivalence. Scoring semantics for true measure-zero events are out of scope; users should instead approximate them with narrow intervals.

\subsection{Unbounded Recursion}\label{sec:examples:7}

We now consider a program with recursion, where control flow may revisit the same expression an unbounded number of times. Such programs are common in probabilistic modeling (e.g., geometric processes), but are challenging for sampling-based methods, which may fail to terminate due to self-loops.

\begin{lstlisting}[aboveskip=1em,belowskip=1em]
    (fix geom x := 
        if x <= 0.5 then true
        else if x <= 0.8 then geom x
        else let y = uniform(0,1) in geom y) 1
\end{lstlisting}

\noindent This program repeatedly evaluates \texttt{geom}, potentially recursing indefinitely when $x \in (0.5, 0.8]$. In the final branch, a fresh sample is drawn and the process continues. While the recursion is unbounded, the key insight is that the observable behavior of the program depends only on which interval the current value of $x$ lies in.

\noindent As in previous examples, \Slice{} extracts the relevant cut set from the comparisons against $0.5$ and $0.8$. These cuts partition the real line into three intervals:
\[
(-\infty, 0.5], \quad (0.5, 0.8], \quad (0.8, +\infty).
\]

\noindent The resulting discretized program is:

\begin{lstlisting}[aboveskip=1em,belowskip=1em]
    (fix geom x := 
        if x <= 0 then true
        else if x <= 1 then geom x
        else let y = discrete(0.5, 0.3, 0.2) in geom y) 2
\end{lstlisting}

\noindent Crucially, the resulting program has a finite state space. This enables exact reasoning via finite-state methods such as Markov chain analysis via Storm.

\subsection{Random interval-covering over $[0,1]$}\label{sec:examples:8}

We now consider a stochastic coverage process over a continuous domain with both higher-order functions and unbounded recursion. The program first samples four cut points $b_1,b_2,b_3,b_4$ from discrete distributions over candidate boundary values, thereby inducing a random partition of $[0,1]$ into subintervals. It then repeatedly samples points from a Gaussian distribution, marking each interval as covered once a sampled point falls inside it. The process stops after a geometrically distributed number of steps, and finally checks whether the entire interval has been covered.

\begin{lstlisting}[aboveskip=1em,belowskip=1em]
let within = fun lo -> fun hi -> fun y ->
    (y >= lo) && (y < hi)
in 

let b = fun _ -> 
    discrete(0.18: 0.05, 0.11: 0.24, 0.21: 0.37, 0.09: 0.58, 0.16: 0.78, 0.25: 0.89)
in

let init = (false, within 0.00 (b ())) :: (false, within (b ()) (b ())) ::
  (false, within (b ()) (b ())) :: (false, within (b ()) 1.00) :: nil
in 

let update = fix update y := fun ys -> 
    match ys with 
    | nil -> nil
    | h :: t -> ((fst h || ((snd h) y)), snd h) :: (update y t)
    end
in 

let step = fun ys -> update (gaussian(0,1)) ys in

let cover = fix cover st :=
if uniform(0,1) < 0.2 then st 
else 
    cover (step st)
in

let is_covered = fix is_covered ys :=
    match ys with 
    | nil -> true 
    | h :: t -> (fst h) && (is_covered t)
    end
in 

let final = cover init in is_covered final
\end{lstlisting}

\noindent \Slice{} again observes that only a finite partition of the real line matters. The comparisons against the grid boundaries induce a cut set that partitions $\R$ into intervals corresponding exactly to these regions. Each sampled point $y$ is therefore abstracted by the index of the region it falls into. 

\noindent Crucially, the resulting program has a \emph{finite state space}: the continuous domain $[0,1]$ is reduced to a finite set of regions, and the coverage state is a tuple of Booleans. Despite the original program featuring unbounded sampling and recursion, its behavior is captured exactly by a finite-state system.
