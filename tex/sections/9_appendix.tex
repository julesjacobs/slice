\section{More motivating examples on language features}\label{ap:mot}
\subsection{Sequential Processes with Iterate}\label{sec:examples:8}

\Slice{} provides the \texttt{iterate} construct to model sequential probabilistic processes. This example simulates a simple weather model where tomorrow's weather depends on today's:

\begin{lstlisting}[aboveskip=1em,belowskip=1em,escapechar=!]
  let weather_transition = fun today ->
      if today < 0.5 then 
          (* If sunny today, likely stays sunny *)
          uniform(0.2, 0.4)
      else  
          (* If rainy today, likely stays rainy *)
          gaussian(0.7, 0.1) in
  let weather_after_3_days = 
      iterate(weather_transition, uniform(0,1), 3) in
  weather_after_3_days < 0.5  (* Is it sunny? *)
\end{lstlisting}

\noindent The \texttt{iterate} function applies the weather transition function three times, starting from a random initial weather state. Each iteration represents one day, with values below 0.5 representing sunny weather and values above 0.5 representing rain. Sunny days tend to stay sunny (uniform between 0.2 and 0.4), while rainy days tend to stay rainy (Gaussian centered at 0.7). The type system ensures that all cuts are properly collected across the iterations, e.g., yielding the type \ft{<0.5} for \textit{today}, \uniform(0.2,0.4), \gaussian(0.7,0.1), and \textit{weather\_after\_three\_days} each. This enables accurate discretization of this sequential process:

\begin{lstlisting}[aboveskip=1em,belowskip=1em,escapechar=!]
  let weather_transition = fun today -> 
    if today < 1 then
        discrete(1, 0)
    else
        discrete(0.0227501, 0.97725) in
  let weather_after_3_days = 
    iterate(weather_transition, discrete(0.5, 0.5), 3) in
  weather_after_3_days < 1
\end{lstlisting}
\noindent
This results in the output \result{0.5334}{0.4666}, which can be obtained from either \Dice or \Roulette as they both support bounded iteration.

\subsection{Lists and Recursion}\label{sec:examples:10}

\Slice{} supports lists and pattern matching, enabling functional list processing with probabilistic elements. The following example demonstrates closures capturing stochastic values:

\begin{lstlisting}[aboveskip=1em,belowskip=1em,escapechar=!]
  let map = fun f -> fix loop lst :=
      match lst with
        nil -> nil
        | head :: tail -> (f head) :: (loop tail)
      end in
  (* Stochastically choose threshold *)
  let threshold = if flip() then 0.3 else 0.7 in
  (* Closure captures the stochastic threshold *)
  let check_threshold = fun x -> x < threshold in
  let measurements = gaussian(0.0, 1.0) :: 
                    gaussian(0.5, 1.0) :: 
                    gaussian(1.0, 1.0) :: nil in
  map check_threshold measurements
\end{lstlisting}

\noindent This gives an output of distributions of lists: $\{\textit{true,true,true}: 0.115341, \textit{true,true,false}: 0.234199, ...\}$ when run with Roulette. The closure \textit{check\_threshold} lexically captures the stochastic \textit{threshold} value, which is randomly chosen to be either 0.3 or 0.7. The type system correctly infers that both threshold values (0.3 and 0.7) must be included as cuts for all Gaussian measurements, yielding the type \ft{<0.3,<0.7} for list elements. This demonstrates how \Slice{} handles higher-order functions with captured stochastic values while maintaining sound discretization.

\subsection{Conditioning}\label{sec:examples:6}

\Slice{} supports conditioning on events through the $\observekw$ construct, allowing for Bayesian inference. The following program, already type-annotated, models the conditional probability that a uniform random variable is less than 0.2, given that it is less than 0.5:

%\begin{lstlisting}[aboveskip=1em,belowskip=1em,escapechar=!]
%    let x = uniform(0.0, 1.0) in
%    let _ = observe (x < 0.5) in
%    x < 0.2
%\end{lstlisting}
%
%\noindent The type annotations show how observation points become cuts:

\begin{lstlisting}[aboveskip=1em,belowskip=1em,escapechar=!]
    let x = (uniform(0.0, 1.0) : !{\ft{<0.2,<0.5}}!) in
    let _ = observe (x < (0.5 : !{\ftb{<0.2,<0.5}{0.5}}!)) in
    x < (0.2 : !{\ftb{<0.2,<0.5}{0.2}}!)
\end{lstlisting}

\noindent The discretized program correctly preserves the conditional probability:

\begin{lstlisting}[aboveskip=1em,belowskip=1em]
    let x = discrete(0.2, 0.3, 0.5) in
    let _ = observe (x < 2) in
    x < 1
\end{lstlisting}

\noindent

In the discrete version, the observation $x < 2$ rules out the case where $x = 2$ (corresponding to the original interval $[0.5, +\infty)$), effectively conditioning on $x$ being in $[0.0, 0.5)$.

\subsection{Higher-Order Functions}\label{sec:examples:7}

\Slice{} supports higher-order functions, enabling functional programming patterns with probabilistic computations. The following function \texttt{mappair} applies a function to both elements of a pair:

\begin{lstlisting}[aboveskip=1em,belowskip=1em,escapechar=!]
  let mappair = fun f -> fun p -> (f (fst p), f (snd p)) in
  let f = fun x -> x < 0.5 in
  let g = fun x -> x < 1.5 in
  let p = (uniform(0,2), gaussian(0,2)) in
  let q = (mappair f) p in
  let r = (mappair g) p in
  if fst q then snd q else 
      if fst r then snd r else fst q
\end{lstlisting}

\noindent The type system correctly infers that cuts from both \texttt{f} and \texttt{g} ($\clt{0.5}$ and $\clt{1.5}$) must be collected for the distributions in \texttt{p}, yielding type the \ft{<0.5,<1.5} for both components. The discretized program preserves the higher-order structure: 

\begin{lstlisting}[aboveskip=1em,belowskip=1em]
  let mappair = fun f -> fun p -> (f (fst p), f (snd p)) in
  let f = fun x -> x < 1 in
  let g = fun x -> x < 2 in
  let p = (discrete(0.25, 0.5, 0.25), 
          discrete(0.598706, 0.174666, 0.226627)) in
  let q = (mappair f) p in
  let r = (mappair g) p in
  if fst q then snd q else 
      if fst r then snd r else fst q
\end{lstlisting}

\noindent \Dice does not support exact inference for higher-order functions, but \Roulette does, and applying it yields the output \result{0.53636}{0.46364}. The continuous distributions in the original program are discretized into three-valued discrete distributions based on the intervals $(-\infty, 0.5)$, $[0.5, 1.5)$, and $[1.5, +\infty)$, while the functional structure remains intact.


\subsection{Mutable State}\label{sec:examples:9}

\Slice{} supports mutable references, allowing imperative-style updates within a probabilistic context. This example models temperature that can be updated based on weather events:

\begin{lstlisting}[aboveskip=1em,belowskip=1em]
  let temperature = ref (uniform(15.0, 25.0)) in
  let weather_event = (if flip() then
      (* Cold front moves in *)
      temperature := gaussian(10.0, 2.0)
    else
      temperature := gaussian(0.0, 1.0)) in
  !temperature < 12.0
\end{lstlisting}

\noindent The reference \texttt{temperature} initially holds a uniform temperature between 15°C and 25°C. With 50\% probability, a cold front updates it to a Gaussian-distributed temperature centered at 10°C. The type system tracks that the dereferenced value will be compared to 12.0, ensuring proper discretization of both the initial uniform distribution and the potential Gaussian update:%, both with float types \ft{<12}:

\begin{lstlisting}[aboveskip=1em,belowskip=1em]
  let temperature = ref (discrete(0, 1)) in
  let weather_event = (if flip() then
      temperature := discrete(0.841345, 0.158655)
    else
    temperature := discrete(1, 0)) in 
  !temperature < 1
\end{lstlisting}
\noindent
\Roulette supports exact inference for mutable state, yielding \result{0.92067}{0.07933}.



\subsection{Indian GPA Problem}\label{sec:gpa}

This example involves both discrete and continuous random variables and models a student's GPA based on nationality (India or USA) and whether they have a perfect record. The GPA is deterministic for perfect students (10.0 for India, 4.0 for USA) but drawn from a uniform distribution otherwise. The program computes the probability that a student's GPA falls below 1.0:

\begin{lstlisting}[aboveskip=1em,belowskip=1em,escapechar=!]
  let nationality = discrete(0.5, 0.5) in
  let perfect = discrete(0.01, 0.99) in
  let gpa = if nationality <= 0 then
          if perfect <= 0 then
            (10.0 : !{\ftb{<1}{10}}!)
          else
            (uniform(0, 10) : !{\ft{<1}}!)
        else
          if perfect <= 0 then
            (4.0 : !{\ftb{<1}{4}}!)
          else
            (uniform(0, 4) : !{\ft{<1}}!)
        : !{\ft{<1}}! in
  gpa < (1.0 : !{\ftb{<1}{1.0}}!)
\end{lstlisting}

\noindent The type system collects the cut $<1$ for all GPA expressions. This splits each uniform distribution into two intervals at the threshold 1.0. The discretized version becomes:

\begin{lstlisting}[aboveskip=1em,belowskip=1em]
  let nationality = discrete(0.5, 0.5) in
  let perfect = discrete(0.01, 0.99) in
  let gpa = if nationality <= 0 then
          if perfect <= 0 then  1
          else
            discrete(0.1, 0.9)
        else
          if perfect <= 0 then  1
          else
            discrete(0.25, 0.75) in
  gpa < 1
\end{lstlisting}

\noindent This gives the output \result{0.17325}{0.82675}. Here, \uniform(0,10) becomes \discrete(0.1, 0.9) representing 10\% probability for $[0,1)$ and 90\% for $[1,10]$. Similarly, \uniform(0,4) becomes \discrete(0.25, 0.75). Constants 10.0 and 4.0 fall into the second interval in the partition $(-\infty, 1) \cup [1,+\infty)$ and are thus both mapped to index 1 in the discretized program.

We also support sequential probabilistic processes with iterate, and lists and recursion, see \Cref{ap:mot} for examples of these features.
\subsection{Partial Discretization for Non-Constant Comparisons}\label{sec:examples:partial1}

Not all programs can be fully discretized. Consider a program where continuous variables are compared directly to each other rather than to constants:

\begin{lstlisting}[aboveskip=1em,belowskip=1em,escapechar=!]
  let x = uniform(0, 1) in
  let y = gaussian(0, 1) in
  if uniform(0,1) < 0.5 then x < y else y < x
\end{lstlisting}

\noindent The type-annotated version reveals that $x$ and $y$ have type \ftt, indicating that no finite set of cuts suffices to fully preserve the semantics of the above program:

\begin{lstlisting}[aboveskip=1em,belowskip=1em,escapechar=!]
  let x = (uniform(0, 1) : !{\ftt}!) in
  let y = (gaussian(0, 1) : !{\ftt}!) in
  if uniform(0, 1) : !{\ft{<0.5}}!) < (0.5 : !{\ftb{<0.5}{0.5}}!
  then x < y else y < x
\end{lstlisting}

\noindent \Slice{} performs partial discretization, i.e., it discretizes only where it is possible:

\begin{lstlisting}[aboveskip=1em,belowskip=1em]
  let x = uniform(0, 1) in
  let y = gaussian(0, 1) in
  if discrete(0.5, 0.5) < 1 then x < y else y < x
\end{lstlisting}
\noindent The branching condition gets discretized, but $x$ and $y$ remain continuous. See \Cref{ap:mot} for another example of partial discretization with no comparisons to continuous distributions.


\subsection{Partial Discretization for Continuous Values without Comparisons}\label{sec:examples:partial2}
The previous example shows a program that can only be partially discretized due to continuous variables being compared directly to each other rather than to constants. If no comparisons are made with continuous distributions, the best \Slice{} can do is also a partial discretization. Consider:

\begin{lstlisting}[aboveskip=1em,belowskip=1em,escapechar=!]
    let x = uniform(0,1) in
    let y = gaussian(0,1) in
    if y < 0.5 then beta(1,1) else uniform(0,2)
\end{lstlisting}
\noindent
Here, \Slice{} does not identify any cuts for the subexpressions $x$ and \ifkw\; $y < 0.5$ \thenkw\; \betafn(1,1) \elsekw\; \uniform(0,2). \Slice{} still preserves the semantics of the original program by not discretizing the return value, setting the cut set of the return values to $\top$. This is because the return value is considered part of the program’s observable behavior, so external code may perform arbitrary comparisons against it, including comparisons to real numbers not present in the program. However, the variables $x$ and $y$ are never used in comparisons, and can hence be discretized:

\begin{lstlisting}[aboveskip=1em,belowskip=1em,escapechar=!]
 let x = uniform(0,1) : !{\ft{}}! in
 let y = gaussian(0,1) : !{\ft{<0.5}}! in
 (if y < (0.5 : !{\ftb{<0.5}{0.5}}!) then beta(1,1) : !{\ftt}! 
   else uniform(0,2) : !{\ftt}!) 
   : !{\ftt}!
\end{lstlisting}

An empty cut set in a float type implies $\mathbb{R}$ with no partitions, or simply the real number line, and thus the probability mass in $(-\infty, +\infty)$ is trivially 1 for any continuous distribution. This leads to \discrete(1,0) for \uniform(0,1). The following is the partially discretized program:

\begin{lstlisting}[aboveskip=1em,belowskip=1em,escapechar=!]
  let x = discrete(1, 0)
  let y = discrete(0.691462, 0.308538) in
  if y < 1 then beta(1,1) else uniform(0,2)
\end{lstlisting}

\subsection{Partial Discretization for Discrete Values without Comparisons}\label{sec:examples:partial3}
We considered the case where no cuts exist for continuous distributions, but here we illustrate the case when no cuts exist for discrete float values. 

\begin{lstlisting}[aboveskip=1em,belowskip=1em,escapechar=!]
   let x = if flip() then 1.0 else 2.0 
   in 3.0
\end{lstlisting}

This yields the following type-annotated program:

\begin{lstlisting}[aboveskip=1em,belowskip=1em,escapechar=!]
 let x = (if flip() then (1.0 : !{\ftb{}{1}}!) 
         else (2.0 : !{\ftb{}{2}}!))
         : !{\ftb{}{1,2}}!
 in 3.0 : !{\ftv{3}}!) : !{\ftv{3}}!
\end{lstlisting}

The float constants 1.0 and 2.0 are discretized away based on their empty cut sets, while the constant 3.0 is preserved as a return value, hence the float type \codetype{\ftv{3}}. For an empty cut set, all float constants in a non-empty value set are trivially mapped to the index 0. From the type-annotated program, the partially discretized program is obtained:

\begin{lstlisting}[aboveskip=1em,belowskip=1em,escapechar=!]
 let x = if flip() then 0 else 0 in
 in 3
\end{lstlisting}

\section{Proofs for Discretization}
\subsection{Proof of Lemma~\ref{lem:type-transformations}}
\begin{proof}\label{proof:type-transformations}
    We proceed by induction on the structure of the typing derivation $\Gamma \vdash e : \tau$. That is, we match each typing rule and show that it remains valid after applying $\discretize{\cdot}$ to the context, expression, and type.
    
    \textbf{Case 1:} $e = x$
    \begin{itemize}
        \item We have that $\discretize{x : \tau} = x$, and since $\Gamma(x) = \tau$, we have that $\discretize{\Gamma}(x) = \discretize{\tau} = \tau$ for $x \in \text{dom}(\Gamma)$. Thus, $\discretize{\Gamma} \vdash x : \discretize{\tau}$.
    \end{itemize}

    \textbf{Case 2:} $e = (c : \float[B;V])$
    \begin{itemize}
        \item If $B = \top$, then $\discretize{c : \float[B;V]} = c$, and $\discretize{\float[B;V]} = \float$. As per the float typing rules in Figure~\ref{fig:typing-float}, $c$ is a constant of type $\float$.
        \item If $B \neq \top$, then $\discretize{e : \float[B;V]} = \finconst{k}{n+1}$ for some $k$ such that $c \in \intervals{B}_k$, and $\discretize{\float[B;V]} = \fin{n+1}$. As per the typing rules in Figure~\ref{fig:typing-general}, $\finconst{k}{n+1}$ is a constant of type $\fin{n+1}$.
    \end{itemize}

    \textbf{Case 3:} $e = (\letkw \; x = e_1 : \tau_1 \; \inkw \; e_2 : \tau_2)$
    \begin{itemize}
        \item The \textsc{Let} typing rule is shown in Figure~\ref{fig:typing-general}. By the inductive hypothesis, we assume $\discretize{\Gamma} \vdash \discretize{e_1 : \tau_1} : \discretize{\tau_1}$ and $\discretize{\Gamma, x : \tau_1} \vdash \discretize{e_2 : \tau_2} : \discretize{\tau_2}$. Then, we can conclude:
        \[ \discretize{\Gamma} \vdash \letkw \; x = \discretize{e_1 : \tau_1} \; \inkw \; \discretize{e_2 : \tau_2} : \discretize{\tau_2}. \]
    \end{itemize}

    \textbf{Case 4:} $e = (e_1 : \float[B_1; V_1] < e_2 : \float[B_2; V_2])$
    \begin{itemize}
        \item The \textsc{Less} typing rule is shown in Figure~\ref{fig:typing-float}. By the inductive hypothesis, we assume $\discretize{\Gamma} \vdash \discretize{e_1 : \tau_1} : \discretize{\tau_1}$ and $\discretize{\Gamma} \vdash \discretize{e_2 : \tau_2} : \discretize{\tau_2}$, where $\tau_1$ and $\tau_2$ are $\float[B_1;V_1]$ and $\float[B_2;V_2]$, respectively. Since both discretized expressions are either floats or finite-typed values, the comparison remains well-typed under standard typing rules:
        \[
        \discretize{\Gamma} \vdash \discretize{e_1 : \float[B_1; V_1]} < \discretize{e_2 : \float[B_2; V_2]} : \discretize{\bool}.
        \]
    \end{itemize}

    \textbf{Case 5:} $e = (\ifkw\; e_1 : \bool \; \thenkw\; e_2 : \tau \; \elsekw\; e_3 : \tau)$

    \begin{itemize}
        \item The \textsc{If} typing rule is shown in Figure~\ref{fig:typing-general}. By the inductive hypothesis, we assume $\discretize{\Gamma} \vdash \discretize{e_1 : \bool} : \discretize{\bool}$, $\discretize{\Gamma} \vdash \discretize{e_2 : \tau} : \discretize{\tau}$, and $ \discretize{\Gamma} \vdash \discretize{e_3 : \tau} : \discretize{\tau}$. Then, we can conclude:
        \[
            \discretize{\Gamma} \vdash \ifkw\; \discretize{e_1 : \bool} \; \thenkw\; \discretize{e_2 : \tau} \; \elsekw\; \discretize{e_3 : \tau} : \discretize{\tau}
        \]
    \end{itemize}

    \textbf{Case 6:} $e = (\uniform(e_1, e_2) : \float[B;V])$

    \begin{itemize}
        \item If $B = \top$, then $\discretize{\float[B;V]} = \float$, and thus:
        \[
            \discretize{\uniform(e_1, e_2) : \float[B;V]} = \uniform(\discretize{e_1 : \tau_1}, \discretize{e_2 : \tau_2}) : \float
        \]
        and by the inductive hypothesis, both $e_1$ and $e_2$ with their respective types $\tau_1 = \float[B_1; V_1]$ and $\tau_2 = \float[B_2; V_2]$ are well-typed, so the result is well-typed under the float rule.

        \item If $B \neq \top$ and $e_1, e_2 \in \mathbb{R}$, then $\discretize{\float[B;V]} = \fin{n+1}$, and thus:
        \[
            \discretize{\uniform(e_1, e_2) : \float[B;V]} = \discrete(p_0, \ldots, p_n) : \fin{n+1}
        \]
        and each $p_k = \text{CDF}(b_{k+1}) - \text{CDF}(b_k)$ satisfies $p_k \in [0,1]$ and $\sum p_k = 1$, so this is well-typed as a finite distribution.

        \item If $B \neq \top$, and $e_1$ or $e_2$ is variable, then the algorithm generates conditionals to evaluate the possible values from $V_1$ and $V_2$ using fresh variables $v_1'$ and $v_2'$, and dispatches to an appropriate discretization of $\uniform$ with constant parameters in each branch. Each branch is well-typed by the inductive hypothesis, and the full expression is well-typed via the typing rules for conditionals and finite types.
    \end{itemize}

    % \textbf{Case 7:} Compound types (functions, pairs, lists, references)

    % \begin{itemize}
    %     \item These follow directly by applying $\discretize{\cdot}$ recursively on the subcomponents of the type and expression. By the inductive hypothesis on each subterm, the transformed expression is well-typed under the transformed type. For instance:
    %     \begin{itemize}
    %         \item If $\tau = A \to B$, then $\discretize{\tau} = \discretize{A} \to \discretize{B}$ and function abstraction preserves typing.
    %         \item If $\tau = A \times B$, then $\discretize{e} = (\discretize{e_1}, \discretize{e_2})$ is typed under $\discretize{A} \times \discretize{B}$.
    %         \item Likewise for lists $\listty{A}$ and references $\texttt{ref}(A)$.
    %     \end{itemize}
    % \end{itemize}

    Hence, each case of the typing derivation is preserved under $\discretize{\cdot}$, which acts on expressions $e : \tau$, types $\tau$, and the context $\Gamma$. Therefore,
    \[
    \discretize{\Gamma} \vdash \discretize{e : \tau} : \discretize{\tau}.
    \]

\end{proof}
