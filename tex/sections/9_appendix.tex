\subsection{Indian GPA Problem}\label{sec:gpa}

This example involves both discrete and continuous random variables and models a student's GPA based on nationality (India or USA) and whether they have a perfect record. The GPA is deterministic for perfect students (10.0 for India, 4.0 for USA) but drawn from a uniform distribution otherwise. The program computes the probability that a student's GPA falls below 1.0:

\todo[inline]{Add conditioning}

\begin{lstlisting}[aboveskip=1em,belowskip=1em,escapechar=!]
  let nationality = discrete(0.5, 0.5) in
  let perfect = discrete(0.01, 0.99) in
  let gpa = if nationality <= 0 then
          if perfect <= 0 then
            (10.0 : !{\ftb{\{<1\}}{\{10\}}}!)
          else
            (uniform(0, 10) : !{\ft{\{<1\}}}!)
        else
          if perfect <= 0 then
            (4.0 : !{\ftb{\{<1\}}{\{4\}}}!)
          else
            (uniform(0, 4) : !{\ft{\{<1\}}}!)
        : !{\ft{\{<1\}}}! in
  gpa < (1.0 : !{\ftb{\{<1\}}{\{1.0\}}}!)
\end{lstlisting}

\noindent The type system collects the cut $<1$ for all GPA expressions. This splits each uniform distribution into two intervals at the threshold 1.0. The discretized version becomes:

\begin{lstlisting}[aboveskip=1em,belowskip=1em]
  let nationality = discrete(0.5, 0.5) in
ountable  let perfect = discrete(0.01, 0.99) in
  let gpa = if nationality <= 0 then
          if perfect <= 0 then  1
          else
            discrete(0.1, 0.9)
        else
          if perfect <= 0 then  1
          else
            discrete(0.25, 0.75) in
  gpa < 1
\end{lstlisting}

\noindent Here, \uniform(0,10) becomes \discrete(0.1, 0.9) representing 10\% probability for $[0,1)$ and 90\% for $[1,10]$. Similarly, \uniform(0,4) becomes \discrete(0.25, 0.75). Constants 10.0 and 4.0 fall into the second interval in the partition $(-\infty, 1) \cup [1,+\infty)$ and are thus both mapped to index 1 in the discretized program.

This gives the output \result{0.17325}{0.82675} when run with \Dice{} and \Roulette{}.

\begin{lstlisting}[aboveskip=1em,belowskip=1em]
(* Random interval-covering over [0,1].

The program keeps sampling points until it random decides to stop (hence an unbounded loop),
then checks whether if by stopping time has covered every part of the interval [0,1]. *)


let within = fun lo -> fun hi -> fun y ->
    (y >= lo) && (y < hi)
in 

let b = fun _ -> discrete(0.18: 0.05, 0.11: 0.24, 0.21: 0.37, 0.09: 0.58, 0.16: 0.78, 0.25: 0.89) in

let init =
(false, within 0.00 (b ())) ::
(false, within (b ()) (b ())) ::
(false, within (b ()) (b ())) ::
(false, within (b ()) 1.00) ::
nil
in 

let update = fix update y := fun ys -> 
    match ys with 
    | nil -> nil
    | h :: t -> ((fst h || ((snd h) y)), snd h) :: (update y t)
    end
in 

let step = fun ys -> update (gaussian(0,1)) ys
in

let cover = fix cover st :=
if uniform(0,1) < 0.2 then st 
else 
    cover (step st)
in

let is_covered = fix is_covered ys :=
    match ys with 
    | nil -> true 
    | h :: t -> (fst h) && (is_covered t)
    end
in 

(* Query if we covered the whole interval *)
let final = cover init in
is_covered final  
\end{lstlisting}

\subsection{Bloom Filter}
\begin{lstlisting}[aboveskip=1em,belowskip=1em]
(* set bf[idx] := true, where idx is 0..3 and bf = (b0, (b1, (b2, b3))) *)
let set_true = fun bf -> fun idx ->
    let b0 = fst bf in
    let tail1 = snd bf in
    let b1 = fst tail1 in
    let tail2 = snd tail1 in
    let b2 = fst tail2 in
    let b3 = snd tail2 in

    if idx <= 0 then
    (true, (b1, (b2, b3)))
    else if idx <= 1 then
    (b0, (true, (b2, b3)))
    else if idx <= 2 then
    (b0, (b1, (true, b3)))
    else
    (b0, (b1, (b2, true)))
in

(* get bf[idx], where idx is 0..3 *)
let get = fun bf -> fun idx ->
    let b0 = fst bf in
    let tail1 = snd bf in
    let b1 = fst tail1 in
    let tail2 = snd tail1 in
    let b2 = fst tail2 in
    let b3 = snd tail2 in

    if idx <= 0 then b0
    else if idx <= 1 then b1
    else if idx <= 2 then b2
    else b3
in

(* Insertion: insert element q into the Bloom filter bf, given hash functions h1 and h2 *)
let insert = fun q -> fun h1 -> fun h2 -> fun bf ->
    let index1 = h1 q in
    let index2 = h2 q in
    let bf1 = set_true bf index1 in
    let bf2 = set_true bf1 index2 in
    bf2
in

(* Search: search for element q in the Bloom filter bf, given hash functions h1 and h2 *)
let search = fun q -> fun h1 -> fun h2 -> fun bf ->
    let index1 = h1 q in
    let index2 = h2 q in
    let b01 = get bf index1 in
    let b02 = get bf index2 in
    b01 && b02
in

(* Hash functions *)
let h1 = fun q ->
    if q <= -2 then 0
    else if -2 < q && q <= 0 then 1
    else if 0 < q && q <= 2 then 2 
    else 3
in

let h2 = fun q ->
    if q <= -2 then 3
    else if -2 < q && q <= 0 then 2
    else if 0 < q && q <= 2 then 1 
    else 0
in

(* Initial, empty Bloom filter *)
let init = (false, (false, (false, false))) in

(* Sample points iid from a continuous distribution *)
let q1 = gaussian(0,1) in
let q2 = gaussian(0,1) in
let q3 = gaussian(0,1) in
let q4 = gaussian(0,1) in

(* Insert sampled points into the Bloom filter *)
let updated_bf_1 = insert q1 h1 h2 init in
let updated_bf_2 = insert q2 h1 h2 updated_bf_1 in
let updated_bf_3 = insert q3 h1 h2 updated_bf_2 in
let updated_bf_4 = insert q4 h1 h2 updated_bf_3 in

(* Probability of obtaining a false positive *)
let q5 = gaussian(0,1) in 
search q5 h1 h2 updated_bf_4    
\end{lstlisting}

\section{List of Supported \Slice{} Distributions}\label{appen:supported-distributions}

The list of distributions supported by \Slice{}, along with their probability density / mass functions, is given in the following table. \Slice{} supports discrete distributions by applying the same cut-set and value-set analysis used for continuous distributions, \emph{provided that the discrete distribution admits a well-defined CDF}. The extension to discrete distributions does not introduce any fundamental changes to the discretization algorithm.

\begin{tabular}{l l @{\qquad} l l}
    \toprule
    \textbf{Distribution} & \textbf{Density} & \textbf{Distribution} & \textbf{Density} \\
    \midrule
    Exponential & $\lambda e^{-\lambda x}$ 
        & Uniform & $\frac{1}{b - a}$ \\
    Laplace & $\frac{1}{2b} e^{-\frac{|x - \mu|}{b}}$ 
        & Gaussian & $\frac{1}{\sqrt{2\pi}\sigma} e^{-\frac{(x - \mu)^2}{2\sigma^2}}$ \\
    Cauchy & $\frac{1}{\pi \gamma \left[1 + \left(\frac{x - x_0}{\gamma}\right)^2\right]}$ 
        & Beta & $\frac{x^{\alpha - 1}(1 - x)^{\beta - 1}}{B(\alpha, \beta)}$ \\
    Student-T & $c \left(1 + \frac{x^2}{\nu} \right)^{-\frac{\nu + 1}{2}}$ 
        & LogNormal & $\frac{1}{x\sigma \sqrt{2\pi}} e^{-\frac{(\ln x - \mu)^2}{2\sigma^2}}$ \\
    Chi-squared & $\frac{1}{2^{k/2} \Gamma(k/2)} x^{k/2 - 1} e^{-x/2}$ 
        & Gamma & $\frac{\beta^\alpha}{\Gamma(\alpha)} x^{\alpha - 1} e^{-\beta x}$ \\
    Logistic & $\frac{e^{-(x - \mu)/s}}{s(1 + e^{-(x - \mu)/s})^2}$ 
        & Pareto & $\frac{\alpha x_m^\alpha}{x^{\alpha + 1}}$ \\
    Rayleigh & $\frac{x}{\sigma^2} e^{-x^2 / (2\sigma^2)}$ 
        & Weibull & $\frac{k}{\lambda} \left( \frac{x}{\lambda} \right)^{k-1} e^{-(x/\lambda)^k}$ \\
    & & Gumbel-1 & $\frac{1}{\beta} e^{-(z + e^{-z})}$,\quad $z = \frac{x - \mu}{\beta}$ \\
    & & Gumbel-2 & $\frac{\alpha \beta x^{-\alpha - 1} e^{-(x/\beta)^{-\alpha}}}{\beta}$ \\
    & & Exponentiated Power & $k \lambda x^{k - 1} e^{-(x/\lambda)^k}$ \\
    \midrule
    \multicolumn{4}{l}{\textbf{Discrete Distributions}} \\
    \midrule

        & Geometric & $(1 - p)^{k - 1} p$ \\

\section{Code Sketches for Scaling Benchmarks}\label{appen:synthetic-sketches}
This section contains code snippets of the programs used in the scaling experiments in Section~\ref{sec:synthetic-benchmarks}. We implemented a Python script that automatically generates these programs based on configurable parameters such as program size, guard structure, and dependency pattern. For reproducibility, we used a fixed random seed to generate each program. All $r_i$ values in the generated programs, where $0 \leq r_i \leq 1$ is randomly chosen, are rounded to two decimal places.

All of these programs follow the same structural pattern: they define a sequence of random variables $X_1,\ldots,X_n$, where each $X_i$ is drawn from a uniform distribution whose parameters depend on the value of a single predecessor variable through a conditional branch of the form
\[
X_i =
  \begin{cases}
    \mathrm{Unif}(a_i,b_i), & X_{\pi(i)} < r_i, \\[2pt]
    \mathrm{Unif}(a'_i,b'_i), & \text{otherwise},
  \end{cases}
\]
for some parent-selection function $\pi : \{2,\ldots,n\} \to \{1,\ldots,i-1\}$.  
Thus each program is a Bayesian network of conditionally independent nodes, differing only in the choice of $\pi(i)$ that determines the dependency pattern.

\section{Proofs for Discretization}
\subsection{Proof of Lemma~\ref{lem:type-transformations}}
\begin{proof}\label{proof:type-transformations}
    We proceed by induction on the structure of the typing derivation $\Gamma \vdash e : \tau$. That is, we match each typing rule and show that it remains valid after applying $\discretize{\cdot}$ to the context, expression, and type.
    
    \textbf{Case 1:} $e = x$
    \begin{itemize}
        \item We have that $\discretize{x : \tau} = x$, and since $\Gamma(x) = \tau$, we have that $\discretize{\Gamma}(x) = \discretize{\tau} = \tau$ for $x \in \text{dom}(\Gamma)$. Thus, $\discretize{\Gamma} \vdash x : \discretize{\tau}$.
    \end{itemize}

    \textbf{Case 2:} $e = (c : \float[B;V])$
    \begin{itemize}
        \item If $B = \top$, then $\discretize{c : \float[B;V]} = c$, and $\discretize{\float[B;V]} = \float$. As per the float typing rules in Figure~\ref{fig:typing-float}, $c$ is a constant of type $\float$.
        \item If $B \neq \top$, then $\discretize{e : \float[B;V]} = \finconst{k}{n+1}$ for some $k$ such that $c \in \intervals{B}_k$, and $\discretize{\float[B;V]} = \fin{n+1}$. As per the typing rules in Figure~\ref{fig:typing-general}, $\finconst{k}{n+1}$ is a constant of type $\fin{n+1}$.
    \end{itemize}

    \textbf{Case 3:} $e = (\letkw \; x = e_1 : \tau_1 \; \inkw \; e_2 : \tau_2)$
    \begin{itemize}
        \item The \textsc{Let} typing rule is shown in Figure~\ref{fig:typing-general}. By the inductive hypothesis, we assume $\discretize{\Gamma} \vdash \discretize{e_1 : \tau_1} : \discretize{\tau_1}$ and $\discretize{\Gamma, x : \tau_1} \vdash \discretize{e_2 : \tau_2} : \discretize{\tau_2}$. Then, we can conclude:
        \[ \discretize{\Gamma} \vdash \letkw \; x = \discretize{e_1 : \tau_1} \; \inkw \; \discretize{e_2 : \tau_2} : \discretize{\tau_2}. \]
    \end{itemize}

    \textbf{Case 4:} $e = (e_1 : \float[B_1; V_1] < e_2 : \float[B_2; V_2])$
    \begin{itemize}
        \item The \textsc{Less} typing rule is shown in Figure~\ref{fig:typing-float}. By the inductive hypothesis, we assume $\discretize{\Gamma} \vdash \discretize{e_1 : \tau_1} : \discretize{\tau_1}$ and $\discretize{\Gamma} \vdash \discretize{e_2 : \tau_2} : \discretize{\tau_2}$, where $\tau_1$ and $\tau_2$ are $\float[B_1;V_1]$ and $\float[B_2;V_2]$, respectively. Since both discretized expressions are either floats or finite-typed values, the comparison remains well-typed under standard typing rules:
        \[
        \discretize{\Gamma} \vdash \discretize{e_1 : \float[B_1; V_1]} < \discretize{e_2 : \float[B_2; V_2]} : \discretize{\bool}.
        \]
    \end{itemize}

    \textbf{Case 5:} $e = (\ifkw\; e_1 : \bool \; \thenkw\; e_2 : \tau \; \elsekw\; e_3 : \tau)$

    \begin{itemize}
        \item The \textsc{If} typing rule is shown in Figure~\ref{fig:typing-general}. By the inductive hypothesis, we assume $\discretize{\Gamma} \vdash \discretize{e_1 : \bool} : \discretize{\bool}$, $\discretize{\Gamma} \vdash \discretize{e_2 : \tau} : \discretize{\tau}$, and $ \discretize{\Gamma} \vdash \discretize{e_3 : \tau} : \discretize{\tau}$. Then, we can conclude:
        \[
            \discretize{\Gamma} \vdash \ifkw\; \discretize{e_1 : \bool} \; \thenkw\; \discretize{e_2 : \tau} \; \elsekw\; \discretize{e_3 : \tau} : \discretize{\tau}
        \]
    \end{itemize}

    \textbf{Case 6:} $e = (\uniform(e_1, e_2) : \float[B;V])$

    \begin{itemize}
        \item If $B = \top$, then $\discretize{\float[B;V]} = \float$, and thus:
        \[
            \discretize{\uniform(e_1, e_2) : \float[B;V]} = \uniform(\discretize{e_1 : \tau_1}, \discretize{e_2 : \tau_2}) : \float
        \]
        and by the inductive hypothesis, both $e_1$ and $e_2$ with their respective types $\tau_1 = \float[B_1; V_1]$ and $\tau_2 = \float[B_2; V_2]$ are well-typed, so the result is well-typed under the float rule.

        \item If $B \neq \top$ and $e_1, e_2 \in \mathbb{R}$, then $\discretize{\float[B;V]} = \fin{n+1}$, and thus:
        \[
            \discretize{\uniform(e_1, e_2) : \float[B;V]} = \discrete(p_0, \ldots, p_n) : \fin{n+1}
        \]
        and each $p_k = \text{CDF}(b_{k+1}) - \text{CDF}(b_k)$ satisfies $p_k \in [0,1]$ and $\sum p_k = 1$, so this is well-typed as a finite distribution.

        \item If $B \neq \top$, and $e_1$ or $e_2$ is variable, then the algorithm generates conditionals to evaluate the possible values from $V_1$ and $V_2$ using fresh variables $v_1'$ and $v_2'$, and dispatches to an appropriate discretization of $\uniform$ with constant parameters in each branch. Each branch is well-typed by the inductive hypothesis, and the full expression is well-typed via the typing rules for conditionals and finite types.
    \end{itemize}

    % \textbf{Case 7:} Compound types (functions, pairs, lists, references)

    % \begin{itemize}
    %     \item These follow directly by applying $\discretize{\cdot}$ recursively on the subcomponents of the type and expression. By the inductive hypothesis on each subterm, the transformed expression is well-typed under the transformed type. For instance:
    %     \begin{itemize}
    %         \item If $\tau = A \to B$, then $\discretize{\tau} = \discretize{A} \to \discretize{B}$ and function abstraction preserves typing.
    %         \item If $\tau = A \times B$, then $\discretize{e} = (\discretize{e_1}, \discretize{e_2})$ is typed under $\discretize{A} \times \discretize{B}$.
    %         \item Likewise for lists $\listty{A}$ and references $\texttt{ref}(A)$.
    %     \end{itemize}
    % \end{itemize}

    Hence, each case of the typing derivation is preserved under $\discretize{\cdot}$, which acts on expressions $e : \tau$, types $\tau$, and the context $\Gamma$. Therefore,
    \[
    \discretize{\Gamma} \vdash \discretize{e : \tau} : \discretize{\tau}.
    \]

\end{proof}

\subsection{Asymptotic Scaling}
We designed a set of synthetic benchmarks to study how exact-inference runtime varies with program size under different dependency structures. Schematically:
%
    \begin{lstlisting}[aboveskip=0.1em,belowskip=.1em]
        let x1 = uniform(0,1) in 
        let x2 = if x1 < r1 then uniform(0,2) else uniform(0,3) in 
        let x3 = if x2 < r2 ...
        ...
        x_n < 0.5
    \end{lstlisting}
%
Each program is a sequence of nested conditionals in which each branch depends on a previous variable sampled from a uniform distribution, terminating at the final condition $x_n < 0.5$. Here $0 \leq r_i \leq 1$ are fixed float constants. Using these programs (listed in Appendix \ref{appen:synthetic-sketches}), we study asymptotic runtime trends for discretization plus exact inference.
 
The programs in \Cref{fig:cond-benchmarks-a} follow the scheme depicted above where the program size is $n$, i.e., the number of comparisons performed is $n$. In \Cref{fig:cond-benchmarks-b}, each $x_i$ does not necessarily depend on $x_{i-1}$ but on some randomly chosen predecessor\footnote{We generate these programs in a randomized manner with a fixed seed for reproducibility}. In \Cref{fig:cond-benchmarks-c}, we additionally choose at random whether the guards of the conditionals and the branches are either some predecessor variable $x_i$ or a  $\uniform$-sampling instruction.
