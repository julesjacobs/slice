\section{Slice by Example}\label{sec:examples}
This section presents simple examples that highlight the key features of our language and compiler \Slice{}, aiming to emphasize how \Slice{} meets the challenge of performing exact inference efficiently. \Slice{} extends a core functional language with traditional programming language constructs such as conditionals, local variables, and functions, augmented with constructs for probabilistic programming such as sampling and conditioning. Each example in the subsections is intended to showcase these features. Later in the section, we also mention examples that can only be partially discretized but nonetheless preserve the semantics across both the original and discretized program. %More examples are highlighted in Appendix~\ref{appen:examples}.

For readability, we use \texttt{flip()} as a shorthand for \texttt{uniform(0,1) < 0.5}, which represents a fair coin flip that returns true or false with equal probability. A ``cut'' is any constant $c$ in a comparison such as $x < c$, where $c$ partitions $\mathbb{R}$ into two intervals $(-\infty, c)$ and $[c, +\infty)$.


\subsection{Simple Branching on a Uniform Distribution}\label{sec:examples:1}

We start with a simple example that illustrates the core idea of \Slice{}. Consider the following program, which models a fair coin flip by comparing the outcome of a uniform sampling to $0.5$:

\begin{lstlisting}[aboveskip=1em,belowskip=1em]
    uniform(0,1) < 0.5
\end{lstlisting}

\noindent \Slice{}'s type system analyzes this program and identifies that the only cut for the continuous distribution is 0.5. This single cut partitions the reals $\R = (-\infty, +\infty)$ into two intervals of equal probability mass: $(-\infty, 0.5)$ and $[0.5, +\infty)$. \Slice{} uses this information to compute a discretization:

\begin{lstlisting}[aboveskip=1em,belowskip=1em]
    discrete(0.5, 0.5) < 1
\end{lstlisting}

\noindent Here, \discrete(0.5, 0.5) represents a choice between two outcomes (0 or 1), each with probability 0.5. The outcome 0 corresponds to the original value being in $(-\infty, 0.5)$, and 1 corresponds to it being in $[0.5, +\infty)$. As such, we have abstracted away the support of the uniform distribution in the original program, replacing it with a discrete choice that preserves the original program's probabilistic behavior with respect to the identified cut. Now, using \Dice{} as a backend for exact inference of discrete probabilistic programs, we can obtain the result \result{0.5}{0.5}.

The transformation to the discretized program is guided by tracking cuts as an intermediate step, which are determined by type inference as shown in the annotated program below:

\begin{lstlisting}[aboveskip=1em,belowskip=1em,escapechar=!]
    (uniform(0, 1) : !{\ft{<0.5}}!) < (0.5 : !{\ftb{<0.5}{0.5}}!)
\end{lstlisting}
Figure~\ref{fig:float-type-def} describes the meaning of a type \lstinline{float[cut set; value set]}.
 \ft{<0.5} indicates then that the cut set contains ``$\clt{0.5}$'' and the value set is $\top$ which indicates the variable can take any value in $(-\infty, +\infty)$. This tells \Slice{} how to partition $\mathbb{R}$. The type \ftb{<0.5}{0.5} indicates that the cut set contains $<0.5$ and the value set contains only the single value $0.5$. This allows \Slice{} to determine to which discrete region the constant $0.5$ belongs to after partitioning $\mathbb{R}$. 

\begin{figure}
\[
\textbf{float}
[
\underbrace{\text{cut-set}}_{\footnotesize\begin{array}{c}\text{set of cuts}\text{ (e.g., }\{<\!0.1, <\!0.5, \leq\!0.8\}\text{)}\\\text{or }\top\text{ (uncut)}\end{array}}
;
\underbrace{\text{value-set}}_{\footnotesize\begin{array}{c}\text{set of concrete values }\text{(e.g., }\{0.1, 0.4, 0.5\}\text{)}\\\text{or }\top\text{ (any value in $\R$)}\end{array}}
]
\]
\caption{The type \lstinline{float[cut-set; value-set]} captures two aspects of a floating-point expression: the cut set is determined by \emph{how the expression is used} (i.e., what it's compared against) and the value set is determined by \emph{what concrete values the expression can take}. The discretization is driven by the cut set: a float value with $n$ cuts is discretized into $n+1$ possible discrete values, each value corresponding to one real-valued interval.}

\end{figure}


\subsection{Branching on Multiple Continuous Variables}\label{sec:examples:2}

\noindent Let us now consider a more complex example with multiple continuous variables and conditionals:

\begin{lstlisting}[aboveskip=1em,belowskip=1em]
    let x = uniform(0, 1) in
    let y = uniform(0, 2) in
    if x < 0.5 then x < 0.2 else y < 0.1
\end{lstlisting}

\noindent In this program, the variable $x$ is drawn from \uniform(0, 1) and is compared against two different constants: $0.5$ and $0.2$. These two cuts partition the real line $\R$ into three intervals: $(-\infty, 0.2)$, $[0.2, 0.5)$, and $[0.5, +\infty)$. Similarly, the variable $y$, drawn from \uniform(0, 2), is compared only with $0.1$. This single cut partitions the real line $\R$ into two intervals, $(-\infty, 0.1)$ and $[0.1, +\infty)$.


This analysis is done by the type inference process, which collects all cuts for each continuous variable. For $x$, the type inference algorithm discovers the cuts $\clt{0.2}$ and $\clt{0.5}$, giving it the type \ft{<0.2,<0.5}. For $y$, it only finds $\clt{0.1}$, giving it the type \ft{<0.1}. This information is captured in the annotated program below (omitting the types for $x$ and $y$):

\begin{lstlisting}[aboveskip=1em,belowskip=1em,escapechar=!]
    let x = uniform(0, 1) : !{\ft{<0.2,<0.5}}! in
    let y = uniform(0, 2) : !{\ft{<0.1}}! in
    if x < (0.5 : !{\ftb{<0.2,<0.5}{0.5}}!) then
      x < (0.2 : !{\ftb{<0.2,<0.5}{0.2}}!)
    else
      y < (0.1 : !{\ftb{<0.1}{0.1}}!)
\end{lstlisting}


\Slice{} replaces the continuous distribution for $x$ with a discrete one that has three outcomes, where the probability of each outcome is the probability mass of the original uniform distribution within the corresponding interval. This results in \discrete(0.2, 0.3, 0.5).
\Slice{} replaces the continuous distribution for $y$ with a discrete one that has two outcomes, where the probability of each outcome is the probability mass of the original uniform distribution within the corresponding interval. This results in \discrete(0.05, 0.95). The comparisons in the program are then transformed to operate on the integer indices of these new discrete intervals, leading to the following discretization:

\begin{lstlisting}[aboveskip=1em,belowskip=1em]
    let x = discrete(0.2, 0.3, 0.5) in
    let y = discrete(0.05, 0.95) in
    if x < 2 then x < 1 else  y < 1
\end{lstlisting}

Using \Dice{}, this yields the output \result{0.225}{0.775}. Note that the original constant $0.5$ is discretized differently: for $x < 0.5$ it is discretized to $2$ and for $y < 0.5$ it is discretized to $1$. This is because the constant $0.5$ falls in the third interval of the split $(-\infty, 0.2) \cup [0.2, 0.5) \cup [0.5, +\infty)$ for $x$ and the second interval for the split $(-\infty, 0.5) \cup [0.5, +\infty)$ for $y$. 

\subsection{Branching on Multiple Discrete Values}\label{sec:examples:3}
The example in Section~\ref{sec:examples:2} involves multiple continuous variables and conditional branches. In a similar fashion, \Slice{} supports multiple discrete values and conditionals. Consider the program:

\begin{lstlisting}[aboveskip=1em,belowskip=1em,escapechar=!]
    let x = if flip() then 0.2 
            else if flip() then 2.5
            else 4.5 in 
    let y = 0.5 in x < y
\end{lstlisting}

This yields the annotated program after type inference:

\begin{lstlisting}[aboveskip=1em,belowskip=1em,escapechar=!]
    let x = if flip() then (0.2 : !{\ftb{<0.5}{0.2}}!)
            else (if flip() then (2.5 : !{\ftb{<0.5}{2.5}}!)
            else (4.5 : !{\ftb{<0.5}{4.5}}!) 
            : !{\ftb{<0.5}{2.5, 4.5}}!)
            : !{\ftb{<0.5}{0.2, 2.5, 4.5}}! in
    let y = 0.5 : !{\ftb{<0.5}{0.5}}! in x < y
\end{lstlisting}

Both $x$ and $y$ can only take on finitely many values --- a fact which is reflected by the value sets in the type annotations. By locating where each value in the value set falls relative to the cuts in the cut set, \Slice{} determines the corresponding interval index for each value. \codetype{\ftb{<0.5}{0.2}} corresponds to the index 0, and types \codetype{\ftb{<0.5}{2.5}}, \codetype{\ftb{<0.5}{4.5}}, and \codetype{\ftb{<0.5}{0.5}} correspond to the index 1. The value sets in types \codetype{\ftb{<0.5}{0.2, 2.5, 4.5}} and \codetype{\ftb{<0.5}{2.5, 4.5}} arise from taking the union of the value sets from each prior conditional branch. This in turn yields the following discretized program:

\begin{lstlisting}[aboveskip=1em,belowskip=1em]
    let x = if flip() then 0
            else if flip() then 1
            else 1 in
    let y = 1
    x < y
\end{lstlisting}

Using \Dice{}, this yields the output \result{0.5}{0.5}.

\subsection{Branching on Continuous Values}\label{sec:examples:4}

In the program above, we always directly compare the continuous samples to constants.
However, the discretization process still works if the continuous samples and constants flow through the program, for instance via a conditional.
Consider the following program, already type-annotated:

%\begin{lstlisting}[aboveskip=1em,belowskip=1em,escapechar=!]
%    let x = if flip() then uniform(0,2) 
%            else gaussian(0,1) in
%    let y = if 1.5 > x
%            then 1.8
%            else 0.3 in
%    x <= y
%\end{lstlisting}
\begin{lstlisting}[aboveskip=1em,belowskip=1em,escapechar=!]
    let x = if flip()
            then (uniform(0,2) : !{\ft{<=0.3,<1.5,<=1.8}}!)
            else (gaussian(0,1) : !{\ft{<=0.3,<1.5,<=1.8}}!)
            : !{\ft{<=0.3,<1.5,<=1.8}}! in
    let y = if (1.5 : !{\ftb{<=0.3,<1.5,<=1.8}{1.5}}!) > x
            then (1.8 : !{\ftb{<=0.3,<1.5,<=1.8}{1.8}}!)
            else (0.3 : !{\ftb{<=0.3,<1.5,<=1.8}{0.3}}!)
            : !{\ftb{<=0.3,<1.5,<=1.8}{0.3,1.8}}! in
    x <= y
\end{lstlisting}
\noindent This program demonstrates how cuts propagate through the control flow. \Slice{} makes a forward pass through the program, and as the float constants 1.5, 1.8, and 0.3 subsequently appear in $y$, the cut sets of the preceding sampling instructions are populated accordingly. The $x \leq y$ comparison at the end renders the cut sets of all subexpressions to be the same: 1.5, 1.8, and 0.3 are the cuts for $x$ hence the type \codetype{\ft{<=0.3,<1.5,<=1.8}} for all subexpressions in the let statement of $x$.
%, and proper indices for the partitioned intervals must be determined hence float types of the form \codetype{{\ftb{<=0.3,<1.5,<=1.8}{\ldots}}} for all subexpressions in the let statement of $y$.
 %The type inference annotates the program as follows:



\noindent Notice that all cuts from the entire program (0.3, 1.5, and 1.8) are collected for the variable $x$, regardless of which branch is taken. These cuts \codetype{<=0.3,<1.5,<=1.8} split the real line into four intervals: $(-\infty, 0.3]$, $(0.3, 1.5)$, $[1.5, 1.8]$, and $(1.8, +\infty)$. Note that 1.5 is excluded from the second interval and included in the third because it comes from a strict `<` comparison. The integer index 1 in the guard of the if statement for $y$ is obtained from the type \codetype{\ftb{<=0.3,<1.5,<=1.8}{1.5}}, 2 is obtained from the type \codetype{\ftb{<=0.3,<1.5,<=1.8}{1.8}}, and 0 is obtained from the type \codetype{\ftb{<=0.3,<1.5,<=1.8}{0.3}}. Applying type-directed discretization yields:

\begin{lstlisting}[aboveskip=1em,belowskip=1em]
    let x = if flip() then
        discrete(0.15, 0.6, 0.15, 0.1)
      else
        discrete(0.617911, 0.315281, 0.0308769, 0.0359303) in
    let y = if 1 > x then 2 else 0 in
    x <= y
\end{lstlisting}

\noindent Using \Dice{}, we get \result{0.8416}{0.1584}. The four probabilities in each \discrete-expression correspond to the probability mass of each of the four intervals. For example, \uniform(0,2) has probability 0.15 in $(-\infty, 0.3]$, 0.6 in $(0.3, 1.5]$, 0.15 in $(1.5, 1.8]$, and 0.1 in $(1.8, +\infty)$. 
%Note that a continuous distribution must be valid in order for its cumulative distribution function (CDF) to be well-defined, and thus for probability mass to be meaningfully assigned to each interval.  It is also normal for some intervals to receive 0 or 1 probability mass—for example, if the entire distribution lies within a single interval and not others.

\subsection{Discrete Latent Variable}\label{sec:examples:5}

Continuous distributions can have parameters that depend on discrete random choices. In this example, a Gaussian distribution's standard deviation is determined by a such a random choice:

\begin{lstlisting}[aboveskip=1em,belowskip=1em,escapechar=!]
    let x = if flip() then 0.5 else 1.5 in gaussian(0, x) < 0.5
\end{lstlisting}

\noindent %This example shows how discrete choices can affect the parameters of continuous distributions. 
The type-annotations reveal how the variable $x$ determines the standard deviation of the Gaussian:

\begin{lstlisting}[aboveskip=1em,belowskip=1em,escapechar=!]
    let x = if flip() then (0.5 : !{\ftb{<=0.5,<=1.5}{0.5}}!)
                      else (1.5 : !{\ftb{<=0.5,<=1.5}{1.5}}!)
             : !{\ftb{<=0.5,<=1.5}{0.5,1.5}}! in
            (gaussian(0, x) : !{\ft{<0.5}}!) < (0.5 : !{\ftb{<0.5}{0.5}}!)
\end{lstlisting}

\noindent Since the variable $x$ is later used as a parameter to the Gaussian distribution, \Slice{} generates a separate case for each possible value that $x$ can take (namely 0.5 and 1.5). To support this, the type system uses non-strict inequalities in the cut sets, enabling these values to be mapped to integer indices starting from 0. Specifically, the value 0.5 corresponds to index 0 via the type \codetype{\ftb{<=0.5,<=1.5}{0.5}}, and 1.5 corresponds to 1 via \codetype{\ftb{<=0.5,<=1.5}{1.5}}. The resulting discretized program then branches on these values and instantiates the corresponding discrete distribution, depending on which standard deviation was selected by the initial flip.

\begin{lstlisting}[aboveskip=1em,belowskip=1em]
    let x = if flip() then 0 else 1 in
    (if x == 0 then  discrete(0.841345, 0.158655)
               else  discrete(0.630559, 0.369441)) < 1
\end{lstlisting}
%
\noindent
Using \Dice{}, this yields the output \result{0.73595}{0.26405}.


\subsection{Conditioning}\label{sec:examples:6}

\Slice{} supports conditioning on events through the $\observekw$ construct, allowing for Bayesian inference. The following program, already type-annotated, models the conditional probability that a uniform random variable is less than 0.2, given that it is less than 0.5:

%\begin{lstlisting}[aboveskip=1em,belowskip=1em,escapechar=!]
%    let x = uniform(0.0, 1.0) in
%    let _ = observe (x < 0.5) in
%    x < 0.2
%\end{lstlisting}
%
%\noindent The type annotations show how observation points become cuts:

\begin{lstlisting}[aboveskip=1em,belowskip=1em,escapechar=!]
    let x = (uniform(0.0, 1.0) : !{\ft{<0.2,<0.5}}!) in
    let _ = observe (x < (0.5 : !{\ftb{<0.2,<0.5}{0.5}}!)) in
    x < (0.2 : !{\ftb{<0.2,<0.5}{0.2}}!)
\end{lstlisting}

\noindent The discretized program correctly preserves the conditional probability:

\begin{lstlisting}[aboveskip=1em,belowskip=1em]
    let x = discrete(0.2, 0.3, 0.5) in
    let _ = observe (x < 2) in
    x < 1
\end{lstlisting}

\noindent
%This results in the output \result{0.4}{0.6}. 
In the discrete version, the observation $x < 2$ rules out the case where $x = 2$ (corresponding to the original interval $[0.5, +\infty)$), effectively conditioning on $x$ being in $[0.0, 0.5)$.

\subsection{Higher-Order Functions}\label{sec:examples:7}

\Slice{} supports higher-order functions, enabling functional programming patterns with probabilistic computations. The following function \texttt{mappair} applies a function to both elements of a pair:

\begin{lstlisting}[aboveskip=1em,belowskip=1em,escapechar=!]
  let mappair = fun f -> fun p -> (f (fst p), f (snd p)) in
  let f = fun x -> x < 0.5 in
  let g = fun x -> x < 1.5 in
  let p = (uniform(0,2), gaussian(0,2)) in
  let q = (mappair f) p in
  let r = (mappair g) p in
  if fst q then snd q else 
      if fst r then snd r else fst q
\end{lstlisting}

\noindent The type system correctly infers that cuts from both \texttt{f} and \texttt{g} (0.5 and 1.5) must be collected for the distributions in \texttt{p}, yielding type the \ft{<0.5,<1.5} for both components. The discretized program preserves the higher-order structure: 

\begin{lstlisting}[aboveskip=1em,belowskip=1em]
  let mappair = fun f -> fun p -> (f (fst p), f (snd p)) in
  let f = fun x -> x < 1 in
  let g = fun x -> x < 2 in
  let p = (discrete(0.25, 0.5, 0.25), 
          discrete(0.598706, 0.174666, 0.226627)) in
  let q = (mappair f) p in
  let r = (mappair g) p in
  if fst q then snd q else 
      if fst r then snd r else fst q
\end{lstlisting}

\noindent \Dice does not support exact inference for higher-order functions, but \Roulette does, and applying it yields the output \result{0.53636}{0.46364}. The continuous distributions in the original program are discretized into three-valued discrete distributions based on the intervals $(-\infty, 0.5)$, $[0.5, 1.5)$, and $[1.5, +\infty)$, while the functional structure remains intact.


\subsection{Mutable State}\label{sec:examples:9}

\Slice{} supports mutable references, allowing imperative-style updates within a probabilistic context. This example models temperature that can be updated based on weather events:

\begin{lstlisting}[aboveskip=1em,belowskip=1em]
  let temperature = ref (uniform(15.0, 25.0)) in
  let weather_event = (if flip() then
      (* Cold front moves in *)
      temperature := gaussian(10.0, 2.0)
    else
      temperature := gaussian(0.0, 1.0)) in
  !temperature < 12.0
\end{lstlisting}

\noindent The reference \texttt{temperature} initially holds a uniform temperature between 15°C and 25°C. With 50\% probability, a cold front updates it to a Gaussian-distributed temperature centered at 10°C. The type system tracks that the dereferenced value will be compared to 12.0, ensuring proper discretization of both the initial uniform distribution and the potential Gaussian update:%, both with float types \ft{<12}:

\begin{lstlisting}[aboveskip=1em,belowskip=1em]
  let temperature = ref (discrete(0, 1)) in
  let weather_event = (if flip() then
      temperature := discrete(0.841345, 0.158655)
    else
    temperature := discrete(1, 0)) in 
  !temperature < 1
\end{lstlisting}
\noindent
\Roulette supports exact inference for mutable state, yielding \result{0.92067}{0.07933}.



\subsection{Indian GPA Problem}\label{sec:gpa}

This example involves both discrete and continuous random variables and models a student's GPA based on nationality (India or USA) and whether they have a perfect record. The GPA is deterministic for perfect students (10.0 for India, 4.0 for USA) but drawn from a uniform distribution otherwise. The program computes the probability that a student's GPA falls below 1.0:

\begin{lstlisting}[aboveskip=1em,belowskip=1em,escapechar=!]
  let nationality = discrete(0.5, 0.5) in
  let perfect = discrete(0.01, 0.99) in
  let gpa = if nationality <= 0 then
          if perfect <= 0 then
            (10.0 : !{\ftb{<1}{10}}!)
          else
            (uniform(0, 10) : !{\ft{<1}}!)
        else
          if perfect <= 0 then
            (4.0 : !{\ftb{<1}{4}}!)
          else
            (uniform(0, 4) : !{\ft{<1}}!)
        : !{\ft{<1}}! in
  gpa < (1.0 : !{\ftb{<1}{1.0}}!)
\end{lstlisting}

\noindent The type system collects the cut $<1$ for all GPA expressions. This splits each uniform distribution into two intervals at the threshold 1.0. The discretized version becomes:

\begin{lstlisting}[aboveskip=1em,belowskip=1em]
  let nationality = discrete(0.5, 0.5) in
  let perfect = discrete(0.01, 0.99) in
  let gpa = if nationality <= 0 then
          if perfect <= 0 then  1
          else
            discrete(0.1, 0.9)
        else
          if perfect <= 0 then  1
          else
            discrete(0.25, 0.75) in
  gpa < 1
\end{lstlisting}

\noindent This gives the output \result{0.17325}{0.82675}. Here, \uniform(0,10) becomes \discrete(0.1, 0.9) representing 10\% probability for $[0,1)$ and 90\% for $[1,10]$. Similarly, \uniform(0,4) becomes \discrete(0.25, 0.75). Constants 10.0 and 4.0 fall into the second interval in the partition $(-\infty, 1) \cup [1,+\infty)$ and are thus both mapped to index 1 in the discretized program.

\subsection{Partial Discretization for non-constant Comparisons}\label{sec:examples:partial1}

Not all programs can be fully discretized. Consider a program where continuous variables are compared directly to each other rather than to constants:

\begin{lstlisting}[aboveskip=1em,belowskip=1em,escapechar=!]
  let x = uniform(0, 1) in
  let y = gaussian(0, 1) in
  if uniform(0,1) < 0.5 then x < y else y < x
\end{lstlisting}

\noindent The type-annotated version reveals that $x$ and $y$ have type \ftt, indicating that no finite set of cuts suffices to fully preserve the semantics of the above program:

\begin{lstlisting}[aboveskip=1em,belowskip=1em,escapechar=!]
  let x = (uniform(0, 1) : !{\ftt}!) in
  let y = (gaussian(0, 1) : !{\ftt}!) in
  if uniform(0, 1) : !{\ft{<0.5}}!) < (0.5 : !{\ftb{<0.5}{0.5}}!
  then x < y else y < x
\end{lstlisting}

\noindent \Slice{} performs partial discretization, i.e., it discretizes only where it is possible:

\begin{lstlisting}[aboveskip=1em,belowskip=1em]
  let x = uniform(0, 1) in
  let y = gaussian(0, 1) in
  if discrete(0.5, 0.5) < 1 then x < y else y < x
\end{lstlisting}
\noindent The branching condition gets discretized, but $x$ and $y$ remain continuous. See \Cref{ap:mot} for another example of partial discretization with no comparisons to continuous distributions.
