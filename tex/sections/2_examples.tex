\section{Slice by Example}\label{sec:examples}
% We illustrate the main \Slice{} constructs—conditionals, local bindings, functions, sampling, and conditioning—through a set of small programs; Appendix~\ref{ap:mot} contains additional examples.

% For readability, we use \flip() as a shorthand for \uniform(0,1) < 0.5, which represents a fair coin flip that returns true or false with equal probability. A cut $\clt{c}$ refers to any constant $c$ that appears in a comparison such as $x < c$, where $c$ divides the real line $\R$ into two intervals: $(-\infty, c)$ and $[c, +\infty)$. When $x$ is compared to several constants, these comparisons introduce a set of cuts $\clt{c_1}, \ldots, \clt{c_n}$, which partitions $\R$ into $n+1$ contiguous intervals $(-\infty, c_1), [c_1,c_2), \ldots, [c_{n-1}, c_n), [c_n, +\infty)$.


% \subsection{Simple Branching on a Uniform Distribution}\label{sec:examples:1}

% We start with a basic example that illustrates the core idea of \Slice{}. 
We can model a fair coin flip by comparing the outcome of a uniform sampling to $0.5$:

\begin{lstlisting}[aboveskip=1em,belowskip=1em]
    uniform(0,1) < 0.5
\end{lstlisting}

% \noindent 

Instead of sampling a real number and then comparing it to $0.5$, we can sample a discrete choice directly:

\begin{lstlisting}[aboveskip=1em,belowskip=1em]
    discrete(0.5, 0.5) < 1
\end{lstlisting}

\noindent Here, \discrete(0.5, 0.5) represents a choice between two outcomes (0 or 1), each with probability 0.5. Intuitively, the large amount of information contained in the uniform sampling of a real number was not necessary; we only needed 1 bit of randomness to determine the outcome.

\textbf{The goal of this paper is to automatically detect such opportunities and transform continuous choices into discrete choices when possible.} We do this by partitioning each continuous variable into intervals, such that numbers in the same interval are equivalent for any comparison that the rest of the program performs on them. Our analysis is formulated as a type system that tracks the partitions, and performing the analysis is done by type inference. After the partitions are determined, we map all real numbers in an interval to a discrete quantity that represents the interval. That is, for a real number $r \in \mathbb{R}$, we forget its exact value, and only remember which interval it belongs to.

For the program above, \Slice{}'s type system identifies that the only cut for the continuous distribution is $\clt{0.5}$. This single cut partitions the reals $\R = (-\infty, +\infty)$ into two intervals: $(-\infty, 0.5)$ and $[0.5, +\infty)$. \Slice{} uses this information to compute a discretization:

The outcome 0 corresponds to the original value being in $(-\infty, 0.5)$, and 1 corresponds to it being in $[0.5, +\infty)$. As such, we have abstracted away the support of the uniform distribution in the original program, replacing it with a discrete choice that preserves the original program's probabilistic behavior with respect to the identified cut. % Now, using \Dice{} as a backend for exact inference of discrete probabilistic programs, we can obtain the result \result{0.5}{0.5}.

In our type system, this is captured as follows, using $\float[B; V]$ types:

\begin{lstlisting}[aboveskip=1em,belowskip=1em,escapechar=!]
    (uniform(0, 1) : !{\ft{<0.5}}!) < (0.5 : !{\ftb{<0.5}{0.5}}!)
\end{lstlisting}
A type $\float[B; V]$ tracks two pieces of information: the cut set $B$, which indicates which intervals are relevant, and the value set $V$ which indicates which values the expression itself can take. Each of these may be $\top$, indicating that we have no information.
Figure~\ref{fig:float-type-def} explains this in more detail.

The type of the uniformly sampled value is \ft{<0.5}, which indicates that only the intervals $(-\infty, 0.5)$ and $[0.5, +\infty)$ are relevant, and the value set is $\top$ which indicates no knowledge of the value itself (because it can be any real value in the range 0 to 1). The type \ftb{<0.5}{0.5} on the constant \emph{does} indicate knowledge of the value itself, which is known to be precisely 0.5. Whenever we have a comparison $x < y$, the type system enforces that the cut sets of both sides are the same, which means that the discretization can map them to discrete quantities in a consistent way.

Figure~\ref{fig:cuts-distr} illustrates how cut sets drive discretization. Notice how a float constant's cut set must contain the constant itself so \Slice{} can determine which discretized interval the constant belongs to after the real line is partitioned. For example, \ftb{<0.5}{0.5} allows \Slice{} to recognize that 0.5 belongs to interval 1, e.g. the region $[0.5,+\infty)$, and to use that value in the discretized program.

\begin{figure}

[
\underbrace{\text{cut-set}}_{\footnotesize\begin{array}{c}\text{set of cuts}\text{ (e.g., }\{<\!0.1, <\!0.5, \leq\!0.8\}\text{)}\\\text{or }\top\text{ (uncut)}\end{array}}
;
\underbrace{\text{value-set}}_{\footnotesize\begin{array}{c}\text{set of concrete values }\text{(e.g., }\{0.1, 0.4, 0.5\}\text{)}\\\text{or }\top\text{ (any value in $\R$)}\end{array}}

\subsection{Branching on Multiple Continuous Variables}\label{sec:examples:2}

\noindent Let us now consider a more complex example with multiple continuous variables and conditionals:

\begin{lstlisting}[aboveskip=1em,belowskip=1em]
    let x = uniform(0, 1) in
    let y = uniform(0, 2) in
    if x < 0.5 then x < 0.2 else y < 0.1
\end{lstlisting}

\noindent In this program, the variable $x$ is drawn from \uniform(0, 1) and is compared against two different constants: $0.5$ and $0.2$. These two cuts $\clt{0.5}$ and $\clt{0.2}$ partition the real line $\R$ into three intervals: $(-\infty, 0.2)$, $[0.2, 0.5)$, and $[0.5, +\infty)$. Similarly, the variable $y$, drawn from \uniform(0, 2), is compared only with $0.1$. This single cut $\clt{0.1}$ partitions the real line $\R$ into two intervals, $(-\infty, 0.1)$ and $[0.1, +\infty)$.


This analysis is done by the type inference process, which collects all cuts for each continuous variable. For $x$, the type inference algorithm discovers the cuts $\clt{0.2}$ and $\clt{0.5}$, giving it the type \ft{<0.2,<0.5}. For $y$, it only finds $\clt{0.1}$, giving it the type \ft{<0.1}. This information is captured in the annotated program below (omitting the redundant types):

\begin{lstlisting}[aboveskip=1em,belowskip=1em,escapechar=!]
    let x = uniform(0, 1) : !{\ft{<0.2,<0.5}}! in
    let y = uniform(0, 2) : !{\ft{<0.1}}! in
    if x < (0.5 : !{\ftb{<0.2,<0.5}{0.5}}!) then
      x < (0.2 : !{\ftb{<0.2,<0.5}{0.2}}!)
    else
      y < (0.1 : !{\ftb{<0.1}{0.1}}!)
\end{lstlisting}


\Slice{} replaces the continuous distribution for $x$ with a discrete one that has three outcomes, where the probability of each outcome is the probability mass of the original uniform distribution within the corresponding interval. This results in \discrete(0.2, 0.3, 0.5).
\Slice{} replaces the continuous distribution for $y$ with a discrete one that has two outcomes, where the probability of each outcome is the probability mass of the original uniform distribution within the corresponding interval. This results in \discrete(0.05, 0.95). The comparisons in the program are then transformed to operate on the integer indices of these new discrete intervals, leading to the following discretization:

\begin{lstlisting}[aboveskip=1em,belowskip=1em]
    let x = discrete(0.2, 0.3, 0.5) in
    let y = discrete(0.05, 0.95) in
    if x < 2 then x < 1 else  y < 1
\end{lstlisting}

%Using \Dice{}, this yields the output \result{0.225}{0.775}.
Note that the original constant $0.5$ is discretized differently: for $x < 0.5$ it is discretized to $2$ and for $y < 0.5$ it is discretized to $1$. This is because the constant $0.5$ falls in the third interval of the split $(-\infty, 0.2) \cup [0.2, 0.5) \cup [0.5, +\infty)$ for $x$ and the second interval for the split $(-\infty, 0.5) \cup [0.5, +\infty)$ for $y$. 

\subsection{Discretizing Float Constants}\label{sec:examples:3}
The example in Section~\ref{sec:examples:2} involves comparisons with literal constant right-hand sides (such as $e < 0.5$). 
\Slice{} does not require the comparison to have a syntactic constant right-hand or left-hand side. Instead, it analyzes the dataflow of the program to determine which constants are relevant, and how these constants are mapped to discrete indices.
Consider the program:

\begin{lstlisting}[aboveskip=1em,belowskip=1em,escapechar=!]
    let x = if flip() then 0.2 
            else if flip() then 2.5
            else 4.5 in 
    let y = 0.5 in x < y
\end{lstlisting}

This yields the annotated program after type inference:

\begin{lstlisting}[aboveskip=1em,belowskip=1em,escapechar=!]
    let x = if flip() then (0.2 : !{\ftb{<0.5}{0.2}}!)
            else (if flip() then (2.5 : !{\ftb{<0.5}{2.5}}!)
            else (4.5 : !{\ftb{<0.5}{4.5}}!) 
            : !{\ftb{<0.5}{2.5, 4.5}}!)
            : !{\ftb{<0.5}{0.2, 2.5, 4.5}}! in
    let y = 0.5 : !{\ftb{<0.5}{0.5}}! in x < y
\end{lstlisting}

Both $x$ and $y$ can only take on finitely many values --- a fact which is reflected by the value sets in the type annotations. By locating where each value in the value set falls relative to the cuts in the cut set, \Slice{} determines the corresponding interval index for each value. \codetype{\ftb{<0.5}{0.2}} corresponds to the index 0, and types \codetype{\ftb{<0.5}{2.5}}, \codetype{\ftb{<0.5}{4.5}}, and \codetype{\ftb{<0.5}{0.5}} all correspond to the index 1. The value sets in types \codetype{\ftb{<0.5}{0.2, 2.5, 4.5}} and \codetype{\ftb{<0.5}{2.5, 4.5}} arise from taking the union of the value sets from each prior conditional branch. This in turn yields the following discretized program:

\begin{lstlisting}[aboveskip=1em,belowskip=1em]
    let x = if flip() then 0
            else if flip() then 1
            else 1 in
    let y = 1
    x < y
\end{lstlisting}

Notice how both $2.5$ and $4.5$ are discretized to $1$, because for the purpose of comparing them to $y = 0.5$, these values are equivalent.

%Using \Dice{}, this yields the output \result{0.5}{0.5}.

\subsection{Branching on Continuous Values}\label{sec:examples:4}

In the two programs above, we directly compare the continuous or discrete samples to constants.
However, the discretization process still works if the both the continuous samples and constants flow through the program, for instance via a conditional.
Consider the following program, already type-annotated:

%\begin{lstlisting}[aboveskip=1em,belowskip=1em,escapechar=!]
%    let x = if flip() then uniform(0,2) 
%            else gaussian(0,1) in
%    let y = if 1.5 > x
%            then 1.8
%            else 0.3 in
%    x <= y
%\end{lstlisting}
\begin{lstlisting}[aboveskip=1em,belowskip=1em,escapechar=!]
    let x = if flip()
            then (uniform(0,2) : !{\ft{<=0.3,<1.5,<=1.8}}!)
            else (gaussian(0,1) : !{\ft{<=0.3,<1.5,<=1.8}}!)
            : !{\ft{<=0.3,<1.5,<=1.8}}! in
    let y = if (1.5 : !{\ftb{<=0.3,<1.5,<=1.8}{1.5}}!) > x
            then (1.8 : !{\ftb{<=0.3,<1.5,<=1.8}{1.8}}!)
            else (0.3 : !{\ftb{<=0.3,<1.5,<=1.8}{0.3}}!)
            : !{\ftb{<=0.3,<1.5,<=1.8}{0.3,1.8}}! in
    x <= y
\end{lstlisting}
\noindent This program demonstrates how cuts propagate through the control flow. \Slice{} makes a forward pass through the program. As the float constants 1.5, 1.8, and 0.3 subsequently appear in $y$, the cut sets of the preceding sampling instructions are populated accordingly. The $x \leq y$ comparison at the end renders the cut sets of all subexpressions to be the same: $\clt{1.5}$, $\cleq{1.8}$, and $\cleq{0.3}$ are the cuts for $x$ hence the type \codetype{\ft{<=0.3,<1.5,<=1.8}} for all subexpressions in the let statement of $x$.
%, and proper indices for the partitioned intervals must be determined hence float types of the form \codetype{{\ftb{<=0.3,<1.5,<=1.8}{\ldots}}} for all subexpressions in the let statement of $y$.
 %The type inference annotates the program as follows:



\noindent Notice that all cuts from the entire program ($\cleq{0.3}$, $\clt{1.5}$, and $\cleq{1.8}$) are collected for the variable $x$, regardless of which branch is taken. These cuts split the real line into four intervals: $(-\infty, 0.3]$, $(0.3, 1.5)$, $[1.5, 1.8]$, and $(1.8, +\infty)$. Note that 1.5 is excluded from the second interval and included in the third because it comes from a strict `<` comparison. The integer index 1 in the guard of the if statement for $y$ is obtained from the type \codetype{\ftb{<=0.3,<1.5,<=1.8}{1.5}}, 2 is obtained from the type \codetype{\ftb{<=0.3,<1.5,<=1.8}{1.8}}, and 0 is obtained from the type \codetype{\ftb{<=0.3,<1.5,<=1.8}{0.3}}. Applying type-directed discretization yields:

\begin{lstlisting}[aboveskip=1em,belowskip=1em]
    let x = if flip() then
        discrete(0.15, 0.6, 0.15, 0.1)
      else
        discrete(0.617911, 0.315281, 0.0308769, 0.0359303) in
    let y = if 1 > x then 2 else 0 in
    x <= y
\end{lstlisting}

\noindent %Using \Dice{}, we get \result{0.8416}{0.1584}. 
The four probabilities in each \discrete-expression correspond to the probability mass of each of the four intervals. For example, \uniform(0,2) has probability 0.15 in $(-\infty, 0.3]$, 0.6 in $(0.3, 1.5]$, 0.15 in $(1.5, 1.8]$, and 0.1 in $(1.8, +\infty)$. 
%Note that a continuous distribution must be valid in order for its cumulative distribution function (CDF) to be well-defined, and thus for probability mass to be meaningfully assigned to each interval.  It is also normal for some intervals to receive 0 or 1 probability mass—for example, if the entire distribution lies within a single interval and not others.

\subsection{Discrete Latent Variable}\label{sec:examples:5}

Continuous distributions can have parameters that depend on discrete random choices. In this example, a Gaussian distribution's standard deviation is determined by a such a random choice:

\begin{lstlisting}[aboveskip=1em,belowskip=1em,escapechar=!]
    let x = if flip() then 0.5 else 1.5 in gaussian(0, x) < 0.5
\end{lstlisting}

\noindent %This example shows how discrete choices can affect the parameters of continuous distributions. 
The type-annotations reveal how the variable $x$ determines the standard deviation of the Gaussian:

\begin{lstlisting}[aboveskip=1em,belowskip=1em,escapechar=!]
    let x = if flip() then (0.5 : !{\ftb{<=0.5,<=1.5}{0.5}}!)
                      else (1.5 : !{\ftb{<=0.5,<=1.5}{1.5}}!)
             : !{\ftb{<=0.5,<=1.5}{0.5,1.5}}! in
            (gaussian(0, x) : !{\ft{<0.5}}!) < (0.5 : !{\ftb{<0.5}{0.5}}!)
\end{lstlisting}

\noindent Since the variable $x$ is later used as a parameter to the $\gaussian$ distribution, \Slice{} generates a separate case for each possible value that $x$ can take (namely 0.5 and 1.5). To support this, the type system uses non-strict inequalities in the cut sets, enabling these values to be mapped to integer indices starting from 0. Specifically, the value 0.5 corresponds to index 0 via the type \codetype{\ftb{<=0.5,<=1.5}{0.5}}, and 1.5 corresponds to 1 via \codetype{\ftb{<=0.5,<=1.5}{1.5}}. The resulting discretized program then branches on these values and instantiates the corresponding discrete distribution, depending on which standard deviation was selected by the initial flip.

\begin{lstlisting}[aboveskip=1em,belowskip=1em]
    let x = if flip() then 0 else 1 in
    (if x == 0 then  discrete(0.841345, 0.158655)
               else  discrete(0.630559, 0.369441)) < 1
\end{lstlisting}

\subsection{Conditioning}\label{sec:examples:6}

\Slice{} supports conditioning on boolean events through the $\observekw$ construct. The following program, already type-annotated, models the conditional probability that a uniform random variable is less than 0.2, given that it is less than 0.5:

%\begin{lstlisting}[aboveskip=1em,belowskip=1em,escapechar=!]
%    let x = uniform(0.0, 1.0) in
%    let _ = observe (x < 0.5) in
%    x < 0.2
%\end{lstlisting}
%
%\noindent The type annotations show how observation points become cuts:

\begin{lstlisting}[aboveskip=1em,belowskip=1em,escapechar=!]
    let x = (uniform(0.0, 1.0) : !{\ft{<0.2,<0.5}}!) in
    let _ = observe (x < (0.5 : !{\ftb{<0.2,<0.5}{0.5}}!)) in
    x < (0.2 : !{\ftb{<0.2,<0.5}{0.2}}!)
\end{lstlisting}

\noindent The discretized program correctly preserves the conditional probability:

\begin{lstlisting}[aboveskip=1em,belowskip=1em]
    let x = discrete(0.2, 0.3, 0.5) in
    let _ = observe (x < 2) in
    x < 1
\end{lstlisting}

\noindent
%This results in the output \result{0.4}{0.6}. 
In the discrete version, the observation $x < 2$ rules out the case where $x = 2$ (corresponding to the original interval $[0.5, +\infty)$), effectively conditioning on $x$ being in $[0.0, 0.5)$.

Conditioning on exact equality is supported as well (e.g., using $\observekw\; (x \leq 0.5 \mathop{\&\&} x \geq 0.5)$). Measure-zero observations are known to be semantically fraught \cite{Jacobs2021ParadoxesProbProg}. Our semantics for observe sidesteps this issue by not renormaling; instead we explicitly keep track of the probability mass of observation failure. Equivalence in this semantics is \emph{stronger} than equivalence after renormalization. Our discretization process preserves equivalence in this stronger sense. The scoring semantics for measure-zero $\observekw$ is not supported in \Slice{}; one must instead condition on a very small but finite interval.
