In this section, we describe the {\em type-directed discretization procedure} that enables the use of exact inference in many programs with continuous distributions. As described in the previous section, after type inference, each float-typed expression carries refinement information in its type $\float[B; V]$ . We describe our discretization algorithm in subsection~\ref{subsec:discretization-alg}, with its formalization in Figure~\ref{fig:discretization-code}. The key insight of our discretization algorithm is that if an expression of type $\float[B;V]$ is finite-cut, we can partition $\mathbb{R}$ into intervals separated by the cuts in $B$ to obtain $\intervals{B}$, giving the finite type $\fin{n+1}$ where $n$ is the number of cuts: $\intervals{B}_k$ is then mapped to $\finconst{k}{n+1}$ for each $k = 0, ..., n$. After, the procedure will analyze $V$: 


\begin{itemize}[leftmargin=*]
    \item[-] if $V = \top$: The expression must be a continuous distribution. Each value in $\fin{n+1}$ occurs with the probability mass $p_k$ of the continuous distribution within $\intervals{B}_k$. This gives a $\discrete(p_0, \ldots, p_{n})$ distribution, which returns a finite type value $\finconst{k}{n+1}$ with probability $p_k$.
    
    \item[-] if $V = \{c_1, ..., c_n\}$: The expression must be a float constant. Each float constant $c \in \{c_1, ..., c_n\}$ is assigned an integer $k$ such that $c \in \intervals{B}_k$ . For each $c$, the finite type value $\finconst{k}{n+1}$ is returned.
\end{itemize}


If an expression with a float type is infinite-cut, proper discretization cannot be performed for that expression and as a result \Slice{} preserves the original floating-point expression. 

\subsection{Discretization Rules}

Our discretization method is defined recursively on the structure of typed expressions. We first define the programs our discretization method produces, which are either fully discretized or partially discretized programs. A fully discretized program contains only discrete distributions.

\begin{definition} [Full discretization]\label{def:full-discr}
    A program can be \textit{fully discretized} by \Slice{} if all its expressions are finite-cut.
\end{definition}

\begin{definition} [Partial discretization]\label{def:partial-discr}
    A program can only be \textit{partially discretized} by \Slice{} if there exists an expression that is infinite-cut.
\end{definition}

\subsection{Algorithm for Discretization}\label{subsec:discretization-alg}
We now describe more formally our discretization algorithm as it is implemented in \Slice{}. Note that \Slice{} only attempts to discretize away expressions with float type $\float[B;V]$, while expressions of all other types preserve their original expressions and types across the discretization. Like in section~\ref{sec:type-inference}, we focus on the same subset language of \Slice{}, enough to capture how our algorithm operates over the full language. 

We define a discretization function $\mathcal{D}\sem{e : \tau}$ that takes in typed expressions and show how it is recursively applied to expressions in our subset language. Variables, let bindings, comparisons, and conditionals all preserve their structure. The crux of our discretization algorithm lies when float constants or continuous distributions are encountered in the AST traversal. Given $B = \{\sim_1\!\!b_1, \ldots, \sim_n\!\!b_n\}$, we let $\text{CDF}(b_i)$ be the measure of a uniform distribution on the interval $(-\infty, b_i)$ if $\sim_i =\ <$ and on the interval $(-\infty, b_i]$ if $\sim_i =\ \leq$. We take $\text{CDF}(b_{0}) = 0$ and $\text{CDF}(b_{n+1}) = 1$. Note that a distribution must be valid before computing its CDF: for distributions with invalid parameters, such as $\uniform(l,r)$ where $l > r$, our implementation generates a runtime error. Figure~\ref{fig:discretization-code} shows the algorithm, which takes in a typed program and outputs a either fully discretized or partially discretized program.

\begin{example}\label{ex:discretization}
 Consider the program with type annotations:

\begin{lstlisting}[aboveskip=1em,belowskip=1em,escapechar=!]
    let x = if (uniform(0,1) : !{\ft{<0.5}}!) < (0.5 : !{\ftb{<0.5}{0.5}}!)
            then (uniform(0,2) : !{\ft{<=0.3,<1.5,<=1.8}}!)
            else (uniform(0,4) : !{\ft{<=0.3,<1.5,<=1.8}}!)
            : !{\ft{<=0.3,<1.5,<=1.8}}! in
    let y = if (1.5 : !{\ftb{<=0.3,<1.5,<=1.8}{1.5}}!) < x
            then (1.8 : !{\ftb{<=0.3,<1.5,<=1.8}{1.8}}!)
            else (0.3 : !{\ftb{<=0.3,<1.5,<=1.8}{0.3}}!)
            : !{\ftb{<=0.3,<1.5,<=1.8}{0.3,1.8}}! in
    x <= y
\end{lstlisting}

The discretization algorithm traverses down the AST and tries to discretize each expression with a float-type. The let bindings for \texttt{x} and \texttt{y}, comparisons, and conditionals are structurally preserved; the discretization function is applied to their subexpressions. Variables pass through unchanged. $\uniform(0,1)$ : \codetype{\ft{<0.5}} is discretized to $\discrete(0.5, 0.5)$, $\uniform(0,2)$ : \codetype{\ft{<=0.3,<1.5,<=1.8}} is discretized to $\discrete(0.15, 0.6, 0.15, 0.1)$, and $\uniform(0,4)$ : \codetype{\ft{<=0.3,<1.5,<=1.8}} is discretized to $\discrete(0.075, 0.3, 0.075, 0.55)$. Float constants 1.5, 1.8, and 0.3 are discretized to 1, 2, and 0, respectively. Since all expressions are finite-cut, the resulting fully discretized program is:

\begin{lstlisting}[aboveskip=1em,belowskip=1em]
    let x = if discrete(0.5, 0.5) then
        discrete(0.15, 0.6, 0.15, 0.1)
      else
        discrete(0.075, 0.3, 0.075, 0.55) in
    let y = if 1 > x then 2 else 0 in
    x <= y
\end{lstlisting}
\end{example}

\subsection{Variable Distribution Parameters}

A key challenge arises when distribution parameters are not constant.
For such parameters, say $e_1 : \float[B_1; V_1]$ and $e_2 : \float[B_2; V_2]$, we use the value sets $V_1$ in $e_1$ or $V_2$ in $e_2$, depending on which parameter(s) is non-constant, to reconstruct the appropriate distribution to compute the CDF on.
Due to the typing rules, each interval induced by $B$ can contain at most one value from $V$; this is the dinguishability constraint. This means that we can uniquely reconstruct the original floating point number from the interval index, by a series of conditionals.
The distribution can then be discretized as if its parameters were constant in each branch of the conditionals.

\begin{example}
    Consider the following program with type annotations:
    \begin{lstlisting}[aboveskip=1em,belowskip=1em,escapechar=!]
        (uniform(0, 
            (if (uniform(0,1) : !{\ft{<0.5}}!) < (0.5 : !{\ftb{<0.5}{0.5}}!) 
            then (1.0 : !{\ftb{<=1.0, <=2.0}{1.0}}!) 
            else (2.0 : !{\ftb{<=1.0, <=2.0}{2.0}}!)) 
            : !{\ftb{<=1.0, <=2.0}{1.0, 2.0}}!)) 
        < 1.0 : !{\ftb{<1.0}{1.0}}!
    \end{lstlisting}

    During type inference, the second parameter of uniform has type $\float[B_{\text{param}}; \{1.0, 2.0\}]$. Note that $B_{\text{param}}$ properly distinguishes \{1.0, 2.0\}. The implementation generates runtime dispatch code that evaluates the parameter expression, matches against possible constant values from the value set, and applies appropriate discretization for each case. The new let bindings for $v_1'$ and $v_2'$ are created so each value in $\{1.0, 2.0\}$ can be uniquely identified by a finite type value and handled efficiently within the discretization logic. The float constants 0.5, 1.0, and 2.0 are mapped to integers 1, 0, and 1 respectively. Since each expression is co-discrete, the resulting fully discretized program is:

    \begin{lstlisting}[aboveskip=1em,belowskip=1em,escapechar=!, mathescape]
        let $v_2'$ = if discrete(0.5, 0.5) < 1 
                     then 0 else 1 in 
        if $v_2'$ == 0 then discrete(1, 0) else discrete(0.5, 0.5) < 1 
    \end{lstlisting}

    In the second conditional, \discrete(1,0) is obtained from the discretization of $\uniform(0, 1.0)$ : \codetype{{\ft{<1.0}}} and \discrete(0.5, 0.5) is obtained from the discretization of $\uniform(0, 2.0)$ : \codetype{{\ft{<1.0}}}. Our algorithm ensures correct discretization even when distribution parameters depend on runtime values.
\end{example}
    
\subsection{Effect of Discretization on Float Types}
In the best case scenario, when all expressions in a given program are finite-cut, \Slice{} fully discretizes the program. In this case, all float typed expressions in the original program are transformed to finite typed expressions after applying $\mathcal{D}$. When some expressions in a given program are infinite-cut, \Slice{} partially discretizes the program; it discretizes away only those finite-cut expressions present in the program, if any. All infinite-cut expressions maintain their original float types after applying $\mathcal{D}$. Figure~\ref{fig:discretization-types} formalizes the transformation of types under $\mathcal{D}$. We assume that $\discretize{.}$ is overloaded: it acts on expressions as shown in Figure~\ref{fig:discretization-code} as well as types as shown in Figure~\ref{fig:discretization-types}. 

\begin{figure}[t]
    \centering
    \begin{align*}
        \discretize{\tau} &= 
        \begin{cases}
            \fin{n+1}, & \text{if } \tau = \float[B; V] \text{ and } B = \{\sim_1\!\!b_1, \ldots, \sim_n\!\!b_n\} \\[0.5em]
            \float, & \text{if } \tau = \float[B; V] \text{ and } B = \top \\[0.5em]
            \discretize{A} \to \discretize{B}, & \text{if } \tau = A \to B \\[0.5em]
            \discretize{A} \times \discretize{B}, & \text{if } \tau = A \times B \\[0.5em]
            \listty{\discretize{A}}, & \text{if } \tau = \listty{A} \\[0.5em]
            \texttt{ref}(\discretize{A}), & \text{if } \tau = \texttt{ref}(A) \\[0.5em]
            \tau, & \text{otherwise}
        \end{cases}
    \end{align*}
    \caption{Transformation of types under $\mathcal{D}$, where $\mathcal{D}$ acts on types.}
    \label{fig:discretization-types}
\end{figure}


We give a lemma stating the relationship between the original program's types and the discretized program's types:

\begin{lemma}[Type Transformation under Discretization]\label{lem:type-transformations}
    Let $\Gamma \vdash e : \tau$ be a well-typed expression in \Slice{}, where $\Gamma$ is a typing environment assigning types to variables. Let $\discretize{e : \tau}$ be the discretization function as defined in Figure~\ref{fig:discretization-code}, and $\discretize{\tau}$ be the type transformation function as defined in Figure~\ref{fig:discretization-types}. Then,
    \[
    \discretize{\Gamma} \vdash \discretize{e : \tau} : \discretize{\tau}
    \]
    where $\discretize{\Gamma}$ is the pointwise transformation of types in $\Gamma$, namely $\discretize{\Gamma}(x) = \discretize{\Gamma(x)}$ for all $x \in \text{dom}(\Gamma)$.
\end{lemma}

\begin{proof}
    We proceed by induction on the structure of the typing derivation $\Gamma \vdash e : \tau$. That is, we match each typing rule and show that it remains valid after applying $\discretize{\cdot}$ to the context, expression, and type.
    
    \textbf{Case 1:} $e = x$
    \begin{itemize}
        \item We have that $\discretize{x : \tau} = x$, and since $\Gamma(x) = \tau$, we have that $\discretize{\Gamma}(x) = \discretize{\tau} = \tau$ for $x \in \text{dom}(\Gamma)$. Thus, $\discretize{\Gamma} \vdash x : \discretize{\tau}$.
    \end{itemize}

    \textbf{Case 2:} $e = (c : \float[B;V])$
    \begin{itemize}
        \item If $B = \top$, then $\discretize{c : \float[B;V]} = c$, and $\discretize{\float[B;V]} = \float$. As per the float typing rules in Figure~\ref{fig:typing-float}, $c$ is a constant of type $\float$.
        \item If $B \neq \top$, then $\discretize{e : \float[B;V]} = \finconst{k}{n+1}$ for some $k$ such that $c \in \intervals{B}_k$, and $\discretize{\float[B;V]} = \fin{n+1}$. As per the typing rules in Figure~\ref{fig:typing-general}, $\finconst{k}{n+1}$ is a constant of type $\fin{n+1}$.
    \end{itemize}

    \textbf{Case 3:} $e = (\letkw \; x = e_1 : \tau_1 \; \inkw \; e_2 : \tau_2)$
    \begin{itemize}
        \item The \textsc{Let} typing rule is shown in Figure~\ref{fig:typing-general}. By the inductive hypothesis, we assume $\discretize{\Gamma} \vdash \discretize{e_1 : \tau_1} : \discretize{\tau_1}$ and $\discretize{\Gamma, x : \tau_1} \vdash \discretize{e_2 : \tau_2} : \discretize{\tau_2}$. Then, we can conclude:
        \[ \discretize{\Gamma} \vdash \letkw \; x = \discretize{e_1 : \tau_1} \; \inkw \; \discretize{e_2 : \tau_2} : \discretize{\tau_2}. \]
    \end{itemize}

    \textbf{Case 4:} $e = (e_1 : \float[B_1; V_1] < e_2 : \float[B_2; V_2])$
    \begin{itemize}
        \item The \textsc{Less} typing rule is shown in Figure~\ref{fig:typing-float}. By the inductive hypothesis, we assume $\discretize{\Gamma} \vdash \discretize{e_1 : \tau_1} : \discretize{\tau_1}$ and $\discretize{\Gamma} \vdash \discretize{e_2 : \tau_2} : \discretize{\tau_2}$, where $\tau_1$ and $\tau_2$ are $\float[B_1;V_1]$ and $\float[B_2;V_2]$, respectively. Since both discretized expressions are either floats or finite-typed values, the comparison remains well-typed under standard typing rules:
        \[
        \discretize{\Gamma} \vdash \discretize{e_1 : \float[B_1; V_1]} < \discretize{e_2 : \float[B_2; V_2]} : \discretize{\bool}.
        \]
    \end{itemize}

    \textbf{Case 5:} $e = (\ifkw\; e_1 : \bool \; \thenkw\; e_2 : \tau \; \elsekw\; e_3 : \tau)$

    \begin{itemize}
        \item The \textsc{If} typing rule is shown in Figure~\ref{fig:typing-general}. By the inductive hypothesis, we assume $\discretize{\Gamma} \vdash \discretize{e_1 : \bool} : \discretize{\bool}$, $\discretize{\Gamma} \vdash \discretize{e_2 : \tau} : \discretize{\tau}$, and $ \discretize{\Gamma} \vdash \discretize{e_3 : \tau} : \discretize{\tau}$. Then, we can conclude:
        \[
            \discretize{\Gamma} \vdash \ifkw\; \discretize{e_1 : \bool} \; \thenkw\; \discretize{e_2 : \tau} \; \elsekw\; \discretize{e_3 : \tau} : \discretize{\tau}
        \]
    \end{itemize}

    \textbf{Case 6:} $e = (\uniform(e_1, e_2) : \float[B;V])$

    \begin{itemize}
        \item If $B = \top$, then:
        \[
            \discretize{\uniform(e_1, e_2)} = \uniform(\discretize{e_1}, \discretize{e_2}) : \float
        \]
        and by the inductive hypothesis, both $e_1$ and $e_2$ are well-typed, so the result is well-typed under the float rule.

        \item If $B \neq \top$ and $e_1, e_2 \in \mathbb{R}$, then:
        \[
            \discretize{\uniform(e_1, e_2)} = \discrete(p_0, \ldots, p_n) : \fin{n+1}
        \]
        and each $p_k = \text{CDF}(b_{k+1}) - \text{CDF}(b_k)$ satisfies $p_k \in [0,1]$ and $\sum p_k = 1$, so this is well-typed as a finite distribution.

        \item If $B \neq \top$, and $e_1$ or $e_2$ is variable, then the algorithm generates conditionals to evaluate the possible values from $V_1$ and $V_2$ using fresh variables $v_1'$ and $v_2'$, and dispatches to an appropriate discretization of $\uniform$ with constant parameters in each branch. Each branch is well-typed by the inductive hypothesis, and the full expression is well-typed via the typing rules for conditionals and finite types.
    \end{itemize}

    % \textbf{Case 7:} Compound types (functions, pairs, lists, references)

    % \begin{itemize}
    %     \item These follow directly by applying $\discretize{\cdot}$ recursively on the subcomponents of the type and expression. By the inductive hypothesis on each subterm, the transformed expression is well-typed under the transformed type. For instance:
    %     \begin{itemize}
    %         \item If $\tau = A \to B$, then $\discretize{\tau} = \discretize{A} \to \discretize{B}$ and function abstraction preserves typing.
    %         \item If $\tau = A \times B$, then $\discretize{e} = (\discretize{e_1}, \discretize{e_2})$ is typed under $\discretize{A} \times \discretize{B}$.
    %         \item Likewise for lists $\listty{A}$ and references $\texttt{ref}(A)$.
    %     \end{itemize}
    % \end{itemize}

    Hence, each case of the typing derivation is preserved under $\discretize{\cdot}$, which acts on expressions $e : \tau$, types $\tau$, and the context $\Gamma$. Therefore,
    \[
    \discretize{\Gamma} \vdash \discretize{e : \tau} : \discretize{\tau}.
    \]

\end{proof}

\begin{example}[Type transformation under discretization]
Let us consider the simplest example (base case) of how the finite-cut expression $\uniform(0, 1)$ : \codetype{\ft{<0.25, <0.75}} is discretized and its type transformed. This expression represents a continuous uniform distribution over the interval $[0,1]$ that is refined with two comparison-based cuts at $\clt{0.25}$ and $\clt{0.75}$. The original type of the expression is:

\[
\tau = \text{\ft{<0.25, <0.75}}.
\]

Applying the discretization function $\discretize{e : \tau}$ to this expression yields:

\[
\discretize{\uniform(0,1) : \tau} = \discrete(0.25, 0.5, 0.25)
\]

where the probabilities in the discrete distribution are computed from the CDF of the uniform distribution over each of the three intervals induced by $B = \{\clt{0.25}, \clt{0.75}\}$. Now applying the type transformation function $\discretize{\tau}$ to this type yields:

\[
\discretize{\tau} = \fin{3}.
\]

Thus, before discretization, we have the typing judgment:
\[
\Gamma \vdash \uniform(0,1) : \text{\ft{<0.25, <0.75}}
\]

and after discretization:
\[
\discretize{\Gamma} \vdash \discrete(0.25,0.5,0.25) : \fin{3}
\]

demonstrating that the discretization procedure produces a well-typed expression under the transformed context and type, as stated in Lemma~\ref{lem:type-transformations}.
\end{example}
