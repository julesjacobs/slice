\section{Evaluation}\label{sec:implem_eval}

As an application of our discretization method, we perform exact inference on models with mixed discrete and continuous distributions. In particular, we integrate \Slice{} with exact discrete inference backends \Dice{} and \Roulette{}, and evaluate the performance of \Slice{}+\Dice{} and \Slice{}+\Roulette{} on (i) a set of constructed benchmarks and (ii) a set of benchmarks taken from the literature, comparing to the state-of-the-art tool \SPPL{} for exact inference of continuous probabilistic programs.

The \Slice{} compiler consists of approximately 3,400 lines of OCaml code (including the lexer, parser, type inference and discretization engines, and \Dice{}/\Roulette{} code generators). We use the OCaml GSL package~\cite{gsl} to compute the CDFs of the probability distributions. The system is open-source and available at \url{https://github.com/[anonymized]}, along with benchmarks, documentation, and a Docker image. All benchmarks were run within that Docker image on an Apple M3 with 16GB RAM.

\subsubsection{New Benchmarks for Scaling}\label{sec:synthetic-benchmarks} We designed a set of benchmarks consisting of conditionally independent programs that can be scaled up in size, with varying dependencies between the program variables. Formally, all programs in our benchmark can be described by the conditional independence structure: $X_i \perp\!\!\!\perp \{\,X_j : j < i, j \neq \pi(i)\,\}
\;\Big|\; X_{\pi(i)}$, where $\pi(i) \in \{1, \ldots, i-1\}$ is the parent index of $X_i$. Schematically:
%
    \begin{lstlisting}[aboveskip=0.1em,belowskip=.1em]
        let x1 = uniform(0,1) in 
        let x2 = if x1 < r1 then uniform(0,2) else uniform(0,3) in 
        let x3 = if x2 < r2 ...
        ...
        x_n < 0.5
    \end{lstlisting}
%
 Each program consists of a sequence of conditionals, where each branch depends on a previous variable sampled from a uniform distribution, proceeding until the final condition $x_n < 0.5$ is reached. Here $0 \leq r_i \leq 1$ are fixed float constants. With these programs, provided in Appendix \ref{appen:synthetic-sketches}, we evaluate how \Slice{} scales for conditional branching and stochastic control flow. 
 
The programs in \Cref{fig:cond-benchmarks-a} follow the scheme depicted above where the program size is $n$, i.e., the number of comparisons performed is $n$. In \Cref{fig:cond-benchmarks-b}, every conditional guard compares against the initial variable $x_1$, so all branches depend on the same root variable. In \Cref{fig:cond-benchmarks-c}, each $x_i$ does not necessarily depend on $x_{i-1}$ but on some randomly chosen predecessor\footnote{We generate these programs in a randomized manner with a fixed seed for reproducability}. In \Cref{fig:cond-benchmarks-d}, we additionally choose at random whether the guards of the conditionals and the branches are either some predecessor variable $x_i$ or a  $\uniform$-sampling instruction.
%

%
 The programs in \Cref{fig:alt-benchmarks-a} also follow the scheme depicted above but where the variables used in the guards cycle with a fixed span size of $m$. For instance, for $m=2$, the pattern is $x_1,x_2,x_1,\ldots$. The programs in \Cref{fig:alt-benchmarks-b,fig:alt-benchmarks-c,fig:alt-benchmarks-d} follow a similar pattern, see Appendix~\ref{appen:synthetic-sketches} for details.

We depict the runtime (in seconds) of (i) \SPPL{} (ii) \Slice{} (discretization only) (iii) \Slice{}+\Dice{} (discretization and subsequent inference using \Dice{}), and (iv) \Slice{}+\Roulette{} (discretization and subsequent inference using \Roulette{}). We specify a timeout of 120 seconds. We evaluate program sizes in increments of 5, from size 0 up to size 50. For each program size, we generate 25 random program instances and report the average runtime over these runs. We note that, although \SPPL{} is implemented in Python while \Slice{} in OCaml, this difference only accounts for a small portion of the observed runtime gap: \Slice{}’s discretization and its integration with efficient exact inference engines allow it to maintain low runtimes as program size increases, whereas \SPPL{}’s performance degrades significantly. As a result, \Slice{} consistently achieves order-of-magnitude improvements across our benchmark suite.

\subsubsection{Existing Benchmarks}\label{sec:fairness-benchmarks}

Next, we evaluate the performance of our \Slice{} framework on two sets of existing benchmarks that \SPPL{} has been evaluated on. We focus on benchmarks which involve continuous sampling and are supported by both \Slice{} and \SPPL{}. 



\Cref{tab:benchmarks_dt} shows benchmarks that originated from~\cite{albarghouthi2017fairsquare}. Performing probabilistic inference on these programs corresponds to evaluating fairness properties of given decision trees, an application area from machine learning. \Cref{tab:benchmarks_psi} depicts benchmarks taken from the PSI~\cite{gehr2016psi} benchmark set. We depict the performance of (i) \Slice{}+\Dice{}, (ii) \Slice{}+\Roulette{}, and (ii) \SPPL{} in seconds. We do not compare to PSI since it has already been shown to be slower than \SPPL{} on these benchmarks.

\paragraph{Results.} Both \Cref{tab:benchmarks_dt} and \Cref{tab:benchmarks_psi} clearly indicate that our \Slice{} framework is highly competitive with the state-of-the-art solver \SPPL{} on the benchmarks it has been evaluated on. In particular, \Slice{}+\Dice{} outperforms \SPPL{} on \emph{every} benchmark, with speed-up factors ranging from $10$ to $215$. \Slice{}+\Roulette{} also outperforms \SPPL{} but with a less significant speed-up. This clearly indicates that our technique of automatically discretizing programs and using discrete inference engines for continuous inference advances the state-of-the-art for exact inference of probabilistic programs.




%Characterizing the fairness of classification algorithms is an interesting application in machine learning~\cite{Dwork2012FairnessAwareness}. FairSquare~\cite{albarghouthi2017fairsquare} and VeriFair~\cite{Bastani2019VeriFair} are two solvers that obtain fairness judgments for large-scale decision-making programs. Prior to SPPL, they were state-of-the-art for verifying the fairness of decision tree classifiers, neural network classifiers, and support vector machine classifiers. We evaluate performance on the decision tree benchmarks, as \Slice cannot solve the neural network and support vector machine benchmarks as they contain multivariate transforms, and show that \Slice{} beats SPPL in performance on such benchmarks.
%
%Table 1 shows the results. The first column shows the decision making program ($DT_n$ means ``decision tree'' with $n$ conditionals), and the remaining columns display the execution times in seconds of Slice with Dice, Slice with Roulette, and SPPL respectively. The last column measures the speedup of \Slice{} over SPPL, where we take the max between Dice and Roulette speedups. The measurements indicate that \Slice{} consistently obtains probability estimates in milliseconds, with up to 200× speedup compared to SPPL. Although FairSquare and VeriFair can compute approximate probabilities that enable them to express more fairness problems, their cost is that their runtime on the decision trees is higher and less predictable than \Slice{} and SPPL which can compute exact probabilities efficiently.
