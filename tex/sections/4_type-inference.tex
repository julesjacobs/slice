\section{Type Inference}\label{sec:type-inference}

Given a source program, \Slice{} first performs type inference on the program, assigning types to every subexpression while simultaneously collecting cuts that will guide the discretization process for subexpressions returning float values. The type system tracks both traditional type information and refinement information specific to floating-point values. In a single pass over the AST, the inference algorithm performs type checking, and specifically for floating-point values, fomulates type checking as a constraint satisfaction problem. For float types $\float[B; V]$, two separate refinement components are maintained:
\begin{itemize}
    \item The \emph{cut set} $B$ collects cuts (e.g., $<\!\!0.5$, $\leq\!\!1.2$) from sites where the expression is compared
    \item The \emph{value set} $V$ tracks concrete float constants that flow to the expression or $\top$ 
\end{itemize}

Both components start at the bottom of their respective lattices ($\emptyset$) and monotonically accumulate information through constraint propagation. The implementation maintains sets as mutable references with attached listeners that propagate updates immediately when new information becomes available. The listeners of a set are triggered when the lattice value goes up in the lattice (it can never go down; the changes are always monotone).
For instance, to maintain the constraint $B_1 \leq B_2$, the system registers a listener that propagates updates from $B_1$ to $B_2$ when $B_1$ goes up.

\subsection{Algorithm for Type Inference}
We describe in detail our type inference algorithm. We specifically focus on how our algorithm generates and solves constraints for float types, in particular continuous distributions and float constants, as type checking for non-float types is standard: all other constructs with non-float return values follow their standard typing rules shown in Figure~\ref{fig:typing-general}. The high-level steps of the algorithm are outlined below, and the pseudocode for the algorithm is outlined in Figure~\ref{fig:inference-code} \katherine{need to cut}.

\begin{enumerate}
    \item \textbf{Initialization of float types.} Start by initializing the $\float[B;V]$ type for all subexpressions that return floats. Specifically, float constants $c$ start with type $\float[\emptyset; \{c\}]$ (empty cut set, singleton value set) and continuous distributions start with type $\float[\emptyset; \top]$ (empty cut set, Top value set). 
    
    \item \textbf{Constraints for conditionals.} Let $V_1, V_2$ and $B_1, B_2$ be the value sets and cut sets of the if- and else- branches in a conditional statment, respectively. Let $V$ and $B$ be the value set and cut set of the entire conditional. Then, $V = V_1 \latticesup V_2$ and $B = B_1 = B_2$.
    
    \item \textbf{Constraints for comparisons.} Comparisons generate answerability constraints which populate cut sets as well as equality constraints between cut sets.
    \begin{enumerate}
        \item \textbf{Answerability constraints.} In particular, $\float[B_1; V_1] < \float[B_2; V_2]$ generates the answerability constraint ``$B_1$ answers $<V_2$''. 
        \begin{itemize}
            \item If $V_1 = V_2 = \top$, then $B_1 = \top$.
            \item If $V_1 \neq \top$ and $V_2 = \top$, then $B_1 = V_1$. If $V_2 \neq \top$ and $V_1 = \top$, then $B_1 = V_2$.
            \item If $V_1 \neq \top$ and $V_2 \neq \top$, then $B_1 = V_2$.  
        \end{itemize}

        \item \textbf{Equality constraints for comparisons.} In particular, for $\float[B_1; V_1] < \float[B_2; V_2]$, set $B_1 = B_2$. 
    \end{enumerate}
    
    \item \textbf{Constraint solver.} Solving all constraints results in an annotated program ready for discretization, with all comparison points captured in the refinements.
\end{enumerate}

\paragraph{Example.}
Consider the type inference process for this simple program:
\begin{lstlisting}[aboveskip=1em,belowskip=1em,escapechar=!]
    let x = if uniform(0,1) < 0.5 
            then uniform(0,2) 
            else gaussian(0,1) in
    let y = if 1.5 < x
            then 1.8
            else 0.3 in
    x <= y
\end{lstlisting}

The inference proceeds as follows. First, we create a new type variable for every subexpression. Second, the constraint solver finds the types of the subexpressions.
This obtains the following annotated program with unknown bags:

\begin{lstlisting}[aboveskip=1em,belowskip=1em,escapechar=!]
    let x = if (uniform(0,1) : !{\codetype{float[$B_1$; $V_1$]}}!) < (0.5 : !{\codetype{float[$B_2$; $V_2$]}}!)
            then (uniform(0,2) : !{\codetype{float[$B_3$; $V_3$]}}!)
            else (gaussian(0,1) : !{\codetype{float[$B_4$; $V_4$]}}!)
            : !{\codetype{float[$B_x$; $V_x$]}}! in
    let y = if (1.5 : !{\codetype{float[$B_5$; $V_5$]}}!) < (x : !{\codetype{float[$B_x$; $V_x$]}}!)
            then (1.8 : !{\codetype{float[$B_6$; $V_6$]}}!)
            else (0.3 : !{\codetype{float[$B_7$; $V_7$]}}!)
            : !{\codetype{float[$B_y$; $V_y$]}}! in
    (x : !{\codetype{float[$B_x$; $V_x$]}}!) <= (y : !{\codetype{float[$B_y$; $V_y$]}}!)
\end{lstlisting}

The bags are then solved in the following manner:

\begin{enumerate}
    \item \textbf{Initialization:}
    Float constants get singleton values in their value sets: $V_2=\{0.5\}$, $V_5=\{1.5\}$, $V_6=\{1.8\}$, $V_7=\{0.3\}$. Continuous distributions get $\top$ values in their value sets: $V_1=V_3=V_4=\top$.

    \item \textbf{Constraints for conditionals:} 
    Set $V_x = V_3 \latticesup V_4 = \top$ and $V_y = V_6 \latticesup V_7 = \{1.8, 0.3\}$. Set $B_x = B_3 = B_4$ and $B_y = B_6 = B_7$.

    \item \textbf{Constraints for comparisons:}
    Comparisons generate answerability constraints which populate the cut bags: 
    \begin{itemize}
        \item `uniform(0,1) < 0.5`: Set $B_1 = V_2$ since $V_1 = \top$. 
        \item `1.5 < x`: Set $B_5 = V_5$ since $V_x = \top$.  
        \item `x <= y`: Set $B_x = V_y$ since $V_x = \top$.
    \end{itemize}
   Enforce equality on cut bags for subexpressions involved in comparisons:
    \begin{itemize}
        \item From `uniform(0,1) < 0.5`: $B_1 = B_2$.
        \item From `1.5 < x`: $B_5 = B_x$.
        \item From `x <= y`: $B_x = B_y$.
    \end{itemize}

    \item \textbf{Solver:}
    All cut bags are therefore in two equivalence classes: $B_{12}$ ($= B_1 = B_2$) and $B_{xy}$ ($=B_x=B_y=B_3=B_4=B_5=B_6=B_7$).
    Combining all constraints on $B_{xy}$ gives the final cut set: $\{ \leq\!0.3, <\!1.5, \leq\!1.8 \}$. The set $B_{12}$ for the first comparison is $\{ <\!0.5 \}$.
\end{enumerate}

This results in the following fully annotated program:

\begin{lstlisting}[aboveskip=1em,belowskip=1em,escapechar=!]
    let x = if (uniform(0,1) : !{\ft{<0.5}}!) < (0.5 : !{\ftb{<0.5}{0.5}}!)
            then (uniform(0,2) : !{\ft{<=0.3,<1.5,<=1.8}}!)
            else (gaussian(0,1) : !{\ft{<=0.3,<1.5,<=1.8}}!)
            : !{\ft{<=0.3,<1.5,<=1.8}}! in
    let y = if (1.5 : !{\ftb{<=0.3,<1.5,<=1.8}{1.5}}!) < x
            then (1.8 : !{\ftb{<=0.3,<1.5,<=1.8}{1.8}}!)
            else (0.3 : !{\ftb{<=0.3,<1.5,<=1.8}{0.3}}!)
            : !{\ftb{<=0.3,<1.5,<=1.8}{0.3,1.8}}! in
    x <= y
\end{lstlisting}

We formalize the above notions in a way that will allow us to in the next section characterize the types of programs our discretization method supports. We first define what it means for a given subexpression with a float type to be co-discrete or co-continuous. 

\begin{definition} [Co-discrete]\label{def:co-discrete}
    An subexpression is \textit{co-discrete} if its cut set is not Top.
\end{definition}

\begin{definition} [Co-continuous]\label{def:co-continuous}
    An subexpression is \textit{co-continuous} if it is not co-discrete.
\end{definition}

The above example shows how comparison points accumulate in the value and cut bags through the constraint propagation mechanism, even when comparisons appear in different branches of the program. Note that all expressions in this example are co-discrete. A simple change at the end of the program from $x \leq y$ to $y$ would have rendered the expressions $1.8$, $0.3$, and $y$ co-continuous, of the types $\float[; 1.8]$, $\float[; 0.3]$, and $\float[; 0.3, 1.8]$ respectively.
